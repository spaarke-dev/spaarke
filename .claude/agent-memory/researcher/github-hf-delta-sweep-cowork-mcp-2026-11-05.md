## 3. What changed our assumptions (read these)
1. **HTML preview in file panes is script-hostile (Secondary, MS-authored).** CoworkDashboard says previews "may block scripts"; CAT observed Teams preview drops inline scripts > ~2000 chars. A large single-file React/Fluent bundle will not run in a preview pane. For Cowork visuals use: static HTML+CSS+inline SVG (works in preview), PNG/XLSX native charts, Adaptive Card (host contract still undocumented), or "download and open in browser" for interactive. Interactive React belongs in the MCP App widget (B), not in a skill `assets/`.
2. **Binary companions may be dropped on plugin install (Secondary, one practitioner)**; Learn does not document it. Harness P7 passed binary-asset-copy via the user-skill upload route. Route-dependent hypothesis -> T2.
3. **Runtime facts (one tenant, 2026-10-05, Secondary)** replace Unknowns in cowork-visual-outputs: openpyxl, python-docx, pdfplumber, PIL are present; no headless browser, ImageMagick, rsvg or inkscape (cannot render HTML->PNG; `soffice`+`pdftoppm` can render docx/xlsx/pdf). Prior note's Python 3.12.15 vs 3.12.14 here = runtime image drifts; always run our own probe.
4. **Word Online attributes tracked changes/comments to the signed-in user** whatever author is requested (packager notes). Our file-producing engines are unaffected; in-place edits of OneDrive files by Cowork would be.
5. **Upload limits page conflict** (100 files / 50 MB uncompressed vs 20 companions / 10 MB).
6. **wiqd 0.24.0 changed validation** (breaking) - re-baseline gates.
