# PP licensing: multiplexing / ISV-hosted / app-only API (2026-10-13)

**Question**: Do non-Power-Apps-licensed customer employees ("workforce contacts") and CIAM partners need licences when they reach Dataverse only through a custom SPA + ASP.NET API using an application user (S2S)? Sanctioned routes, request limits, PAYG, ISV programs.

**Primary doc**: Power Platform Licensing Guide, **October 2026**, 30 pp. (cover also carries stray "February 2023"). Fetched from `https://go.microsoft.com/fwlink/?linkid=2085130` -> `cdn-dynmedia-1.microsoft.com/.../Power-Platform-Licensing-Guide.pdf`; byte-identical to licensingschool.co.uk Oct-2026 copy. Multiplexing p.24; External Users p.25; Power Pages p.16-19; Dataverse p.20-23; Power Apps p.6-8. Also D365 Licensing Guide Oct 2026 (`linkid=866544`) pp.71-73 and the March 2021 "Licensing brief: Multiplexing Overview" (download.microsoft.com/download/3/D/4/3D42BDC2-6725-4B29-B75A-A5B04179958B/Licensing_Brief_PLT_Multiplexing.pdf).

**Microsoft states**
- PLG p.24: multiplexing "does not reduce the number of subscription licenses of any type required"; any user that "inputs data into, queries, views data from or otherwise accesses Power Apps, Power Automate and Power Pages apps, directly or indirectly must be properly licensed"; tiers between do not matter. PLG p.25 External Users = not employees/30h-week contractors of "Customer or its Affiliates"; external route = Power Platform USL, Power Pages auth/anon capacity, Power Automate per-flow/Process, limited D365/M365 rights. NO "Dataverse API only" SKU and NO "Power Apps for external users" SKU in the guide.
- Multiplexing Overview 2021 (D365 section): "Third party integrations ... all users of the integrating service must also be licensed for the Microsoft service ... even if those users never use the Microsoft service directly"; "Pooled connections use a non-interactive user account"; Q7 frontline workers copying data into Dataverse need licences. D365 guide p.72: internal users accessing "through a website or via an API to a separate service" must be licensed.
- Learn `create-users` (ms.date 2026-10-02): non-interactive users "don't need a license"; app users = S2S, "common way that apps registered on Microsoft Marketplace access the Dataverse data of their subscribers"; up to 7 non-interactive per env, unlimited app users; guests "should also have a license from the environment's tenant. License from Guest user's tenant isn't considered as valid" (tension with `powerapps-flow-licensing-faq` + `share-app-guests`: per-user plans recognised cross-tenant; per-app are env-scoped, not cross-tenant).
- Learn `api-request-limits-allocations` (ms.date 2026-09-08): paid per-user 40,000 req/24h; per-app + PAYG + D365 Team Member 6,000; Power Pages login 200. Non-licensed (application/non-interactive/admin/system) = ONE tenant pool: Power Apps (all licences) 25,000 base, no per-licence accrual; D365 500,000 + 5,000/USL (max 10M). Requests add-on +50,000/24h, "can't currently assign ... to users or flows". Enforcement not before >=6 months after Power Automate usage reporting GA; MS "reserves the right to enforce". PPR reports exclude Dataverse/Power Apps calls.
- PAYG (`pay-as-you-go-meters` 2026-08-14; `pay-as-you-go-issues-faq` 2026-09-22): Power Apps per-app $10/active user/app/month, "active user is someone who opens an app"; Power Pages $4 authenticated / $0.30 anon per site per month (counted by login to a website; authenticated = unique Dataverse contact id per FAQ); guests "Yes" can use apps w/o licences; PAYG Power Pages meter "internal or external ... any authentication provider". Requests meter "not yet available". Power Apps per-app SKU end-of-sale to new customers 2026-01-02 (PAYG per-app meter still listed).
- Power Pages Web API doc (2026-10-09): "not optimized for third-party services or application integration"; Web API ops require Power Pages licence. Power Pages code sites (SPA/React) support Entra ID + Entra External ID + generic OIDC.
- ISV: `isv-app-license` (ms.date 2025-01-14): named-user ISV licences enforced for **model-driven apps only**, customers need base licence; requires ISV Connect (now "ISV Success for Business Applications"/"Frontier Accelerate for Marketplace", doc 2026-10-05). Nothing found on ISV-hosted-in-own-tenant licensing. Microsoft licensing page `microsoft.com/licensing/guidance/Power-Platform` says nothing on app users/service principals/ISVs.
- D365 guide p.72: D365 "outsourced business services" prohibition (D365 apps only; Spaarke runs no D365 apps).

**Interpretation (not stated by MS)**: In Model 1 the ISV is the "Customer" for the tenant, so the customer's employees are "External Users" by definition; no documented ISV carve-out; app-only API = textbook multiplexing; PAYG Power Apps meter likely does not count users who never open a Power App, so PAYG does not obviously cover custom-API users. Conservative sanctioned routes: Power Pages (auth capacity packs or PAYG $4, ideally with SPA code site or at minimum Power Pages as the gateway) for external partners; Power Apps Premium/PAYG-per-app for workforce staff who open the model-driven app; a custom API for unlicensed users is the unconfirmed gap.
