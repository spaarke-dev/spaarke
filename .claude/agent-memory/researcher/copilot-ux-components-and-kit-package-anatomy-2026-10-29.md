## 2026-10-29: Copilot UX components + enablement-kit package anatomy

**Question**: What are Copilot UX components (GA), where do they render, how shipped; exact file trees for Cowork/Claude plugins, M365 app packages, SharePoint .agent, Agent Builder zip, site provisioning.

**Findings**:
- **UX components = SPFx 1.24 Copilot components (GA 2026-10-28)** implementing the MCP Apps model. `BaseCopilotComponent` (`@microsoft/sp-copilot-component`), manifest `componentType: CopilotComponent`, `copilotType: Ux`, `tools[]` with Zod `propertiesSchema`, `availableDisplayModes` inline/fullscreen. Ships in `.sppkg` with `copilot/{manifest.json, declarativeAgent.json (v1.8), ai-plugin.json, instruction.txt}` + `config/copilot-agent.json`. Tools are served by a SharePoint-hosted MCP endpoint `https://<tenant>.sharepoint.com/_api/mcp/beta/spfx?solutionId=…`; the UI renders in an iframe (`/_layouts/15/PortableComponent.aspx`).
- **Bridge**: `copilotBridge.updateModelContextAsync` / `sendFollowUpMessageAsync` (10 KB text context cap, blocks rather than truncates), `requestDisplayModeAsync`, `requestSizeChangeAsync`. The SPFx bridge documents **no callTool**; data and writes go through `spHttpClient` / `msGraphClientFactory` / AadHttpClient, with `webApiPermissionRequests` approved by an admin in the API access page (the approval is tenant-wide across all SPFx solutions).
- **Tier**: **admin only**. The tenant app catalog upload must use "Enable this app and add to all sites" (required), followed by **Add to Teams** (Sync to Teams) to publish the declarative agent. Each user needs the **M365 Copilot add-on USL** (no PAYG alternative), and so does dev/Workbench use. Store distribution goes through the **SharePoint Store** (AppSource), not the Teams Store.
- **Surfaces at GA**: M365 Copilot (web and desktop) and Copilot in Teams (web and desktop). **Not GA**: iOS/Android, **Cowork**, standard-chat "Copilot plug-in model" packaging, and other surfaces (all "planned", no dates).
- **External MCP Apps** (DA + MCP plugin, `RemoteMCPServer`, plugin-mcp-apps 09-30): `_meta.ui.resourceUri`, `callServerTool`, `sendMessage`, `updateModelContext`, `openLink`, and fullscreen are supported. Not supported: uploadFile, modal, partial input, `frameDomains`, and `destructiveHint`. The sandbox host is `{sha256(mcp-domain)}.widget-renderer.usercontent.microsoft.com`. In MDA, MCP-app HTML can call `window.parent.parent.postMessage({eventName:'powerapps.copilot.chat.action',…})` and the app handles it with `Xrm.Copilot.addActionHandler`. Store validation (10-23) has Adaptive Card rules only, no widget rules.
- **Cowork plugin zip**: manifest v1.28 (or 1.29 via wiqd) contains `agentSkills[]` (max 20) and `agentConnectors[]` (remote MCP over streamable HTTP, OAuthPluginVault, or DCR in Cowork only). `atk import openplugin` reads `.claude-plugin/plugin.json`, `.mcp.json`, and `skills/`. It **drops commands/, agents/, hooks/**. There is no UI/widget support in Cowork docs. `wiqd` CLI is in preview. The DA manifest v1.9 `agent_skills` allows a maximum of 8.
- **SharePoint**: the `.agent` (JSON, schemaVersion 0.2.0, customCopilotConfig/gptDefinition, saved in SiteAssets/Copilots) **is retiring**. From mid-Nov 2026 there is no new `.agent`; Agent Builder replaces it, and `.agent` files stop working after March 2027. **Site skills** live at `/Agent Assets/Skills/<name>/SKILL.md`; any Edit user can create one, they can't call external systems, and they can create lists. Agent Builder zip = manifest + icon only (embedded files stripped). Site templates/scripts: creation requires a SharePoint admin; owners can only apply published templates. PnP PowerShell needs your own Entra app (mandatory since 2024-09-09, consent needed).
