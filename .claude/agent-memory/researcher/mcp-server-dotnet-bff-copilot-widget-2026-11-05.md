## Q1 .NET MCP SDK (Cited: NuGet API + package contents inspected 2026-11-05, csharp-sdk releases)
- Packages: `ModelContextProtocol.AspNetCore` -> `ModelContextProtocol` -> `ModelContextProtocol.Core`; plus `ModelContextProtocol.Extensions.Apps` (MCP Apps) and `.Extensions.Tasks`. Latest **2.3.1 (2026-11-03, security fix hardening authenticated *stateful* sessions)**; 2.0.0 stable 2026-07-28 ("stable alignment with MCP 2026-07-28"); 2.3.0 2026-10-20; 1.4.2 (2026-11-03) = 1.x maintenance line. License Apache-2.0. TFMs net8/9/10 (+netstandard2.0 for non-Asp packages). 49.7M downloads (ModelContextProtocol).
- Spec support: 2026-07-28 natively (server/discover, no sessions); older revisions (2025-11-25 and earlier) via initialize handshake on the same endpoint. `HttpServerSessionMode` { Stateless (DEFAULT since 2.0), Stateful, StatefulForInitializeClients (hybrid, 2.2.0) }; bool `Stateless` is shorthand. Set it explicitly. Stateful-only knobs (IdleTimeout, MaxIdleSessionCount, EventStreamStore) obsolete (MCP9006). Roots/Sampling/Logging APIs deprecated (MCP9005). Tasks moved out of Core.
- Footprint (net10.0): Core.dll 1.30 MB + ModelContextProtocol.dll 91 KB + AspNetCore.dll 151 KB + Apps.dll 36 KB. Transitive: `Microsoft.Extensions.AI.Abstractions 10.11.0`, `Microsoft.Extensions.Logging.Abstractions 10.0.13`, `Microsoft.Extensions.Caching.Abstractions 10.0.13`, `Microsoft.Extensions.Hosting.Abstractions 10.0.13`; ASP.NET shared framework. **BFF currently has `Microsoft.Extensions.AI 10.3.0` (csproj line 82)** -> the MCP SDK will lift AI.Abstractions to 10.11.0 (latest Microsoft.Extensions.AI is 10.11.0): expect to bump `Microsoft.Extensions.AI`/`.OpenAI` together; run publish-size delta per CLAUDE.md s10. (Inference, verify with restore.)
- Minimal server (Cited, docs/concepts + WeatherAppServer sample):
```csharp
builder.Services.AddMcpServer()
  .WithHttpTransport(o => o.SessionMode = HttpServerSessionMode.Stateless)
  .WithTools<DecisionTools>()           // or WithToolsFromAssembly()
  .WithResources<DecisionWidgetResources>()
  .WithMcpApps();                       // processes [McpAppUi]
app.MapMcp("/mcp").RequireAuthorization("McpPolicy");
```
- Tools: `[McpServerToolType]` class, `[McpServerTool(Name=, Title=, ReadOnly=true, Destructive=, Idempotent=, OpenWorld=, UseStructuredContent=true, OutputSchemaType=)]` (property names verified in Core XML docs), `[Description]`. `[McpMeta("key","value")]` attribute on tools/resources (string/double/bool ctor). Return `CallToolResult { Content=[TextContentBlock], StructuredContent=JsonElement, Meta=JsonObject }` (`Result.Meta` exists). Non-object structured results are emitted directly, not wrapped in `{result:..}` (2.0 breaking). `Tool.OutputSchema` any JSON Schema 2020-12 (spec 2026-07-28 loosened).
- DI + user context (Cited, identity.md/httpcontext.md/stateless.md): declare `ClaimsPrincipal? user` param on a tool (injected, excluded from schema); or `IHttpContextAccessor`. In **stateless mode the server uses `HttpContext.RequestServices` and `ScopeRequests=false`** so scoped services behave exactly like a minimal-API endpoint (middleware-set state is visible to tools) - good fit for BFF's per-request OBO services. `AddAuthorizationFilters()` + `[Authorize(Roles/Policy)]` on tools removes unauthorized tools from `tools/list` (per-user tool lists; compatible with DA dynamic discovery). `WithRequestFilters(AddCallToolFilter)` for audit.
- Auth integration (Cited): `ProtectedMcpServer` sample: `AddAuthentication(o => o.DefaultChallengeScheme = McpAuthenticationDefaults.AuthenticationScheme).AddJwtBearer(...).AddMcp(o => o.ResourceMetadata = new() { AuthorizationServers=[..], ScopesSupported=[..], ResourceDocumentation=.. })`; `MapMcp().RequireAuthorization().RequireCors(...)`. `McpAuthenticationHandler` serves PRM (RFC 9728) and adds `WWW-Authenticate: Bearer resource_metadata=...` on challenge; `McpAuthenticationEvents.OnResourceMetadataRequest` to customize. BFF already has multi-scheme auth (`AuthorizationModule.cs` AzureAd via Microsoft.Identity.Web + Ciam scheme + audience merging in PostConfigure ~lines 115-160) -> MCP endpoint needs its own policy bound to the AzureAd scheme; check ValidAudiences can carry the extra Teams-portal Application ID URI (see Q3).
- **Strict Accept check**: `StreamableHttpHandler` returns 406 unless the client Accept contains BOTH `application/json` and `text/event-stream` (source line ~75). OfficeDev/microsoft-365-agents-toolkit issue #15421 (opened 2026-03-04, closed 2026-03-05 "fixed", MS platform said it already sends both) reported DA RemoteMCPServer sending only `application/json`. Test: DA call against the BFF; if 406, relax via middleware that adds the header (workaround), do not fork the SDK.
- Resources: `[McpServerResource(UriTemplate="ui://spaarke/decision-grid", Name=, MimeType=McpApps.HtmlMimeType)]`, return HTML string; `ResourceContents.Meta`/`Resource.Meta` exist. Binary via BlobResourceContents.

## Q2 MCP Apps from C# (Cited)
- **Official C# support exists**: `ModelContextProtocol.Extensions.Apps` 2.3.1 (Apache-2.0, **Experimental diagnostic MCPEXP003** - add `<NoWarn>MCPEXP003</NoWarn>`). API: `[McpAppUi(ResourceUri="ui://..", Visibility=[McpUiToolVisibility.Model|App])]` + `.WithMcpApps()` -> writes `_meta.ui` on the tool; `McpApps.SetAppUi/SetResourceUi/ApplyAppUiAttributes/GetUiCapability(ClientCapabilities)` (checks `extensions["io.modelcontextprotocol/ui"].mimeTypes`); `McpUiResourceMeta{Csp{ConnectDomains,ResourceDomains,FrameDomains,BaseUris},Permissions,Domain,PrefersBorder}`; consts `McpApps.HtmlMimeType="text/html;profile=mcp-app"`, `ExtensionId`. Sample: csharp-sdk `samples/WeatherAppServer` (net10.0, `ui/weather-forecast.html`, `[McpMeta("ui", """{"csp":{"connectDomains":[..]},"prefersBorder":true}""")]` on the resource, `StructuredContent` in tool result). Caveat: helper writes only `_meta.ui`, NOT the legacy flat `_meta["ui/resourceUri"]` that the TS helper (and the trey-research sample's tools/list) also emits; Learn M365 table lists `_meta.ui.resourceUri` as supported -> flat key likely unneeded; **Unknown**, test by omitting; fallback `[McpMeta("ui/resourceUri","ui://..")]`. Also CSP: sample puts it on resource `_meta` (list); spec says read-time `_meta` wins -> put the same `_meta.ui` in `ReadResourceResult` content `Meta` too; which one M365 Copilot reads = Unknown.
- Also official: Azure Functions MCP extension .NET MCP Apps (`[McpToolTrigger]`, `[McpMetadata(json)]`, `[McpResourceTrigger]` with MimeType; blog 2026-02-23, Cited) - alt hosting, not BFF.
- TS widget side: `@modelcontextprotocol/ext-apps` 2.0.4 (MIT, 2026-10-27; peer deps react 17-19, zod ^4, @modelcontextprotocol/{core,client,server} ^2). Repo sample trey-research uses an older version, DA v1.6, app manifest 1.24 and inline key `x-mcp_tool_description` (Learn 2.4 name is `mcp_tool_description`) - do not copy those versions.
- Spec: MCP Apps = first official extension `io.modelcontextprotocol/ui`; **stable spec 2026-01-26** (ext-apps repo `specification/2026-01-26/apps.mdx`, "Stable"); draft dir exists. Contract: tool `_meta.ui{resourceUri,visibility:["model","app"]}`; resource `_meta.ui{csp{connectDomains,resourceDomains,frameDomains,baseUriDomains},permissions{camera,microphone,geolocation,clipboardWrite},domain,prefersBorder}`; MIME `text/html;profile=mcp-app`; View->Host: `ui/initialize` (-> protocolVersion, hostCapabilities, hostInfo, hostContext) then `ui/notifications/initialized`; Host MUST NOT send anything before `initialized`; then `ui/notifications/tool-input`, `tool-result` (full CallToolResult), `host-context-changed`, `ui/resource-teardown`; View requests `tools/call`, `resources/read`, `ui/message`, `ui/open-link`, `ui/request-display-mode`, `ui/update-model-context`, `ui/download-file`, size-changed notification. HostContext: theme, styles(CSS vars), displayMode, availableDisplayModes, containerDimensions, locale, timeZone, safeAreaInsets, toolInfo. Display modes inline/fullscreen/pip. **Spec does not mention modals.** App-only tools: host MUST NOT list tools lacking "model"; MUST reject app calls to tools lacking "app"; same-server only. Default CSP: default-src 'none', script/style 'self' 'unsafe-inline', img/media 'self' data:, connect-src 'none'. Draft spec example limits for hosts: ~50 tools, 30 s timeout, 10 MB results (examples, not requirements).
- **M365 Copilot support** (plugin-mcp-apps ms.date 2026-09-30, tables identical to the May copy in knowledge/): `app.ontoolinput/ontoolresult` ok, `callServerTool` ok, `sendMessage` ok, `openLink` ok, `updateModelContext` ok, `sendSizeChanged` ok, theme/displayMode/locale/safeArea via getHostContext ok; NOT supported: `ontoolinputpartial`, `ontoolcancelled`, `onhostcontextchanged` (theme not pushed after init), `onteardown`, `availableDisplayModes`, `toolInfo`, `uploadFile`, `requestModal`, `_meta.ui.permissions`, `prefersBorder`, `domain`, `frameDomains`, `baseUriDomains`, `destructiveHint/openWorldHint/idempotentHint` (only `readOnlyHint`). `requestDisplayMode` = "full screen only". whats-new (March 2026): "Widgets can render inline or in full-screen mode". UX guide also describes optional "side-by-side" workspace with chiclet card + handoff to full app; whether side-by-side == fullscreen surface = Unknown (test via requestDisplayMode). `visibility` supported (`openai/visibility` row checked; `widgetAccessible` not). Troubleshooting (2026-07-14): `<a>` links don't work -> `app.openLink`; host container already scrolls (set overflow hidden); put widget-only data in `_meta`, model summary in `content`, big payloads cause "tool result expiry"; `content`=model data, `structuredContent`=data+widget, `_meta`=widget only.
- **Modal**: host modal `requestModal` unsupported in M365 Copilot (Cited). In-iframe overlay (e.g., Fluent v9 Dialog) is plain HTML in the sandboxed iframe: nothing documented either way -> **Unknown**; inline iframe height is capped (Cowork: up to 640 px, 200-720 px wide) so an overlay is clipped to the iframe unless fullscreen. Avoid `window.alert/confirm` (sandbox `allow-modals` unknown). Safer: master-detail panel in fullscreen, or `openLink` to the Console/MDA URL (https only, confirm dialog). Test: widget with Fluent Dialog in inline and fullscreen in M365 Copilot web and desktop.

## Q4 Hosting cautions
- MCP spec 2026-07-28 = stateless; C# default Stateless: no sessions, no GET/DELETE, no unsolicited server push; each POST response is an SSE stream that completes with the JSON-RPC response (per docs). Therefore no ARR affinity needed: App Service **Session affinity can be set Off for stateless apps** (Learn configure-common, ms.date 2026-04-13). Turn Always On. Set HTTP/2 optional. Stateful would require affinity + in-memory sessions (2 h idle, 10,000 max) + restarts lose sessions (Cited) - avoid.
- App Service ~230 s idle/response limit at the load balancer, not configurable (Secondary: MS Q&A 2023 "~230 secs"; Learn FAQ page did not carry it). Irrelevant if tool calls are short; MS says tool calls < 30 s (wiqd/Cowork requirement, Cited). No background/long-running via MCP in v1.
- Standard request headers in 2026-07-28: POST must carry `Mcp-Method`, `Mcp-Name`, `MCP-Protocol-Version`; proxies/WAF/APIM/Front Door must pass them (Cited changelog). Do not terminate/transform Accept.
- Copilot limits: M365 Copilot rate limit for widget->server calls, widget HTML size cap, initial-render timeout, tool result size = **Unknown** (not documented for M365 Copilot; Cowork-only numbers: 60 widget calls/min/conversation, 10 s `ui/initialize`, result inlined <= 64 KiB else omitted, https/wss CSP origins <= 16 - prior note). Tests: T3/T4 in the prior note. Learn: tool description > 1,024 chars ignored; "excessively large" tool responses cause tool result expiry -> keep `content` small, rows in `_meta`/app-only paging tool. HTML must be one self-contained file (vite-plugin-singlefile); widget fetches go through host `tools/call` (credentials never in iframe).

## Q5 Security (Cited: MCP security best practices (draft), authorization 2026-07-28, Learn)
- Servers MUST implement PRM (RFC 9728); MUST validate tokens were issued for them as audience (RFC 8707 resource); "MUST NOT accept or transit any other tokens"; token passthrough explicitly forbidden - BFF **OBO (new token for Graph/Dataverse) is compliant, forwarding the inbound token is not**. 401 invalid/expired; 403 + `WWW-Authenticate: Bearer error="insufficient_scope", scope=.., resource_metadata=..` for step-up; put all required scopes in one challenge; scope minimization (do not publish omnibus scopes). Confused deputy applies to OAuth *proxy* servers (static client id + DCR + consent cookie) - not to a BFF that is just a resource server behind Entra with pre-registered clients (do not build an OAuth proxy in the BFF). State-handle hijacking: bind any server-minted handle to verified user id (stateless spec replaced session ids with handles). SSRF is client/AS side.
- Tool poisoning / injection: Copilot screens tool definitions with RAI + XPIA classifiers only under dynamic discovery (Cited); no documented guard on tool *results*. Treat Decision Record text as untrusted: render as text in widget (no innerHTML), keep long free-text out of `content` where the model reads it, narrow descriptions, no tools that mutate based solely on model-read record text. (Engineering judgement, not a cited MS statement.)
- Consent: first use of an MCP plugin shows a connect card; after that tools with `readOnlyHint:true` run without prompt; non-read tools prompt each time (Always allow only for non-consequential); `destructiveHint` ignored in M365 Copilot (so mark writes by omission of readOnlyHint) (Cited confirmation-prompts 2026-07-14 + plugin-mcp-apps). App-initiated `tools/call` for write tools: M365 Copilot behavior Unknown (spec says hosts SHOULD require approval for readOnlyHint:false app tools - draft spec); test.

## Q7 MCP spec status (Cited: modelcontextprotocol.io 2026-07-28 changelog)
- Current revision **2026-07-28**. Changes: no protocol sessions / no `Mcp-Session-Id` (SEP-2567); no `initialize`, per-request `_meta` carries version + client capabilities (SEP-2575); `server/discover` RPC MUST; `subscriptions/listen` replaces GET + resources/subscribe; ping/logging/setLevel/roots-list-changed removed; Tasks -> extension `io.modelcontextprotocol/tasks`; MRTR (Multi Round-Trip Requests: `InputRequiredResult`, `resultType` on all results) replaces server-initiated elicitation/sampling/roots requests; tools/prompts/resources lists carry `ttlMs` + `cacheScope`; `Mcp-Method`/`Mcp-Name` headers; schemas = any JSON Schema 2020-12 and structuredContent any JSON value; resource-not-found code -32602; RFC 9207 `iss` validation; DCR (RFC 7591) **deprecated** in favor of Client ID Metadata Documents; Roots/Sampling/Logging deprecated (12-month window); HTTP+SSE transport Deprecated; error codes -32020..-32099 reserved.
- **SEP-1865 MCP Apps**: official extension `io.modelcontextprotocol/ui`, stable spec dated **2026-01-26**; client matrix lists Microsoft 365 Copilot, Claude, VS Code Copilot, Goose, Postman, MCPJam, Archestra (matrix cells render empty in fetch - Secondary on exact flags); C# SDK still labels it experimental (MCPEXP003).
