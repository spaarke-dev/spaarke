# Copilot as a Spaarke UI surface + Frontier (2026-11-05)

Labels: **Cited** (Microsoft primary), **Secondary** (non-Microsoft/Message Center mirror), **Unknown** (no source; tenant test given). Builds on: m365-copilot-agent-guest-crosstenant-2026-10-08, cowork-visual-outputs-2026-11-05, mcp-ecosystem-publishing-2026-09-01, word-vs-cowork-plugin-kinds-harvey-legora-tuning-2026-11-02, copilot-ux-components-and-kit-package-anatomy-2026-10-29.

## Headline
Copilot is a real **summary + action + deep-link** surface for attorneys today, not a place to mount the Console. A whole multi-view workspace is possible mechanically (one self-contained HTML, every API call proxied as an app-visibility MCP tool) but Microsoft's own UX guidance says a widget that "resembles your entire SaaS product exceeds scope". Recommended shape: MCP server (BFF-adjacent) with task tools + 3-5 focused widgets + `openLink`/"open in app" handoff to the Console.

## Q1 MCP Apps surfaces and limits
- **M365 Copilot (DA + RemoteMCPServer plugin)**: plugin-mcp-apps (ms.date 2026-09-30, no preview banner) = interactive widgets in "Copilot chat"; test at m365.cloud.microsoft/chat. GA web+desktop (Tech Community, March 2026, Secondary-ish MS blog); mobile "following this spring" (no confirmation found); Gov clouds RM564608 (pub 2026-05-27, upd 2026-08-18) lists Desktop and Web only. Teams/Outlook/Word pane rendering of *external* MCP Apps: **Unknown** (only SPFx UX components are documented GA in Teams web/desktop, 2026-10-28). Prereq table (prerequisites, 2026-09-30): "MCP Apps (interactive UI widgets)" and "Custom actions" are available in Copilot Chat with no usage billing and no Copilot licence. **Cited**.
- **Cowork** (mcp-apps-support, ms.date 2026-09-08, upd 2026-11-03; whats-new: added June 2026 with GA): inline + fullscreen (pip rejected); inline width 200-720 px, height up to 640 px; result inlined <=64 KiB else omitted (widget pulls via tools/call); widget->host only `resources/read`, `tools/call`, `ui/message`; 60 widget calls/min/conversation; `ui/initialize` within 10 s; `ui/update-model-context` NOT supported; user creds never in iframe (host attaches auth); CSP `connectDomains`/`resourceDomains`/`frameDomains` honored (<=16 origins, https/wss only, filtered by package `validDomains`, fail-closed); permissions camera/microphone/geolocation/clipboardWrite; sandboxed cross-origin per-server origin - widgets from same server share cookies/storage (so storage exists, origin-scoped; persistence Unknown); HTML must be inline/data: URLs; serve as `text` not blob; mime `text/html;profile=mcp-app`; `openLink` https only + confirm dialog. **Cited**.
- **M365 Copilot vs Cowork deltas** (plugin-mcp-apps table): M365 Copilot supports `updateModelContext`/widgetState, `requestDisplayMode` "full screen only", `frameDomains` NOT supported, `destructiveHint` ignored, `uploadFile`/modal/ontoolinputpartial not supported. Cowork supports frameDomains but not update-model-context. Same MCP server must tolerate both. **Cited**.
- **UX guidance** (plugin-mcp-apps-ui-guidelines, ms.date 2026-06-18): inline = glanceable, <=2 actions, no tabs/pagination; "side-by-side" (optional) = workspace panel with header that "includes a handoff option to the full application" (`setOpenInAppUrl` supported) and chiclet card in chat; "Avoid global navigation, multi-tab systems, settings panels... If the experience resembles your entire SaaS product, it exceeds scope." Fluent 2 tokens expected (Fluent v9 is aligned). **Cited**. Troubleshooting (07-14): tool descriptions >1,024 chars ignored; anchor tags don't open - use openLink; "Fullscreen isn't supported across all Copilot hosts".
- **Whole workspace as one widget**: no documented size cap on widget HTML or payload for M365 Copilot (Unknown); Cowork 64 KiB only applies to inlined result. Because creds never reach the iframe, the only authed path to our BFF is host-proxied `tools/call` (app-only tools via `_meta.ui.visibility:["app"]`); direct `fetch` to BFF would need connectDomains and would carry no user token. Console code page assumes Xrm/MSAL context -> needs a transport adapter (no code reuse "as is"). OpenAI Apps SDK widgets (`text/html+skybridge`, `window.openai`) also run.

## Q3 Calling the BFF from an agent
- Three registration models (do not conflate): (a) **DA action** `RemoteMCPServer` in plugin manifest 2.4 - works only inside that DA; Learn: "aren't enabled as standalone experiences" (confirmation-prompts 2026-07-14); dynamic tool discovery default (`functions:[]`, `run_for_functions:["*"]`, ms.date 2026-10-28; RAI/XPIA screen on new tools; user-specific tool lists allowed; confirmation text not customizable). (b) **App-manifest `agentConnectors`** plugin (manifest 1.29/1.30; Cowork requires a static tool-description file; others per host) (configure-plugin-mcp-servers 2026-10-28). (c) **Federated connector** (admin-created or Gallery-published): Chat, Agents, Cowork, Word/Excel/PowerPoint/Outlook, Researcher (read-only there); Entra SSO / OAuth 2.0 / none; **user needs M365 Copilot licence**; no "Installed for". "Register once, appears everywhere" = (c), but MCP Apps rendering and DA instructions do not come with it (Unknown).
- Versions: DA schema **v1.9** (2026-09-30/10-22: `agent_skills` <=8, Fabric capability; actions 1-10; instructions <=8,000), plugin **v2.4** (MCP runtime), app manifest **v1.30**. All numbered - MCP needs no devPreview. `ConnectionVault` auth is devPreview only. **Cited**.
- Auth for MCP plugins: Entra SSO, DCR, OAuth 2.0 (static); API key not for DA MCP. **Entra has no RFC 7591 endpoint -> use static OAuth or Entra SSO** ("Microsoft Entra ID doesn't provide an RFC 7591 registration endpoint; use static OAuth registration"). Redirect `https://teams.microsoft.com/api/platform/v1.0/oAuthRedirect`. **Cited**.
- **April 2026 issues, status**:
  1. OBO - our side (BFF).
  2. Parameter fidelity: no documented fix; MCP route gives `inputSchema` + <=1,024-char descriptions ("Use this function when..."); instructions pattern "Only call the tool if necessary inputs are available; otherwise, ask the user" (declarative-agent-instructions, upd 2026-10-27); pinned functions allow `states.reasoning.instructions`; MS warns model changes alter behaviour. Net: **Unknown** if fixed - run eval.
  3. Read confirmation cards: MCP: set `annotations.readOnlyHint:true` in `tools/list` => no confirmation after first-use consent; API/OpenAPI: `x-openai-isConsequential: false`; GETs prompt only on first connect. Plugin schema 2.4 `confirmation.type` enum is `None|AdaptiveCard` and `isNonConsequential` (no effect when OpenAPI `x-oai-isConsequential` set - note spelling `oai` vs `openai` differs across two Learn pages). First-use consent card cannot be removed. **Cited**; whether `type: None` still gets stripped = Unknown.
  4. Preferring native Dataverse knowledge: no documented control. `behavior_overrides.special_instructions.discourage_model_knowledge` only suppresses *model* knowledge. Keep DA free of knowledge capabilities; name the tool in instructions. **Unknown**.
  5. devPreview/BOM: MCP plugin 2.4 and agentConnectors are GA schemas; BOM fragility **Unknown**.
- Multi-tenant: AnyTenant auth config usable by an agent installed in a customer home tenant = still **Unknown** (T257 open question).

## Q4 Federated connectors for Word (Harvey pattern)
Documented hosts include Copilot in Word/Excel/PowerPoint/Outlook (federated-connectors-overview, ms.date 2026-10-19). Custom connector created in the customer tenant (Copilot > Connectors > Gallery > Created by your org > Connect to MCP server; Entra SSO registration ID or OAuth registration ID from Teams Dev Portal; Global/AI admin). Write tools need per-tool user approval (Allow once/conversation/Always); read tools never ask. Tools only, no skill instructions. **Cited**. ## Q5 Licensing/cost
- DA with MCP actions and MCP Apps in Copilot Chat: no Copilot licence, no metering **while the DA has no tenant-data knowledge** (prerequisites, 2026-09-30). Users still need to be in the home tenant (guest limitation, prior note).
- Federated connectors: M365 Copilot licence required (troubleshooting list). SPFx UX components: Copilot add-on USL.
- Cowork: access only via a **spending policy that selects Cowork** (usage-based billing; cowork-access ms.date 2026-11-04); "tool and skill calls ... count toward consumption"; per-user licence requirement not stated = Unknown. Cost is borne by the *customer tenant*, never by Spaarke.
- Dataverse MCP charges (prior note) unchanged; BYO-MCP certification GA target Dec 2026 (RM576752, prior note).

## Q6 Frontier
- **Definition** (learn get-started-frontier, ms.date 2026-10-15, upd 2026-11-04): "preview access to innovative and emerging capabilities in Microsoft 365 before ... general availability"; **tenant-level opt-in** in M365 admin center > Copilot > Settings > "Copilot Frontier": No access (default) / All users / Specific users and groups; roles AI Admin, Security Admin or Office Apps Admin; use needs Copilot licence per feature (Copilot features); **from Nov 2026 unified release preferences: admins no longer need a Copilot licence to opt in**; Frontier agents only to enrolled users since 2026-03-29; allow "agents built by Microsoft"; admin account must itself be enrolled/licensed to see Cowork settings. Targeted release retires Jan 2027 (Frontier users stay).
- **Terms**: governed by Product Terms + DPA; "may be modified, suspended, or discontinued"; no standard support/SLA; **no HIPAA BAA; "do not comply with ISO 27001, 27002, 27018"**; some paid. Individuals can opt in on web apps (consumer plans).
- **Graduation evidence (dated)**: Cowork Frontier -> GA 2026-06-16 (whats-new: "Local browser use moved from Frontier to GA" Aug 2026); Legal Agent Frontier (Apr 2026) -> "Copilot for legal" GA from mid-Oct 2026 (MC1509799, pub 2026-10-15) and "The Legal Agent is being retired" (existing users lose access); Office in Copilot Frontier 2026-10-09 -> GA mid-Nov 2026 (MC1530611); App skill (Frontier, Sept 2026) still preview; Home tab Chat/Cowork toggle Frontier (Oct 2026).
- **Currently Frontier (Learn/whats-new)**: App skill / Copilot Managed Runtime (preview), Home tab, Cowork Frontier-public plugins (Accounting), Frontier model options (Fable 5.1, GPT 5.5), AI-enabled Cloud PCs, Project Opal, Dataverse MCP Server (Frontier) via Agent 365 Tools (prior note). Agent 365 GA 2026-05-01 ($15/user standalone or in E7 "Frontier Suite" $99) (Secondary, MS blog 4516295).
- **ISV/partner path**: Frontier page never mentions partners/ISVs (Cited negative). Partner levers are different programs: **Frontier Accelerate for Marketplace** (announced 2026-09-28; MAICPP member; ISV Success auto-enrolled to Premium; Build & Publish/Grow/Differentiate; Azure credits up to $30k; commercial, not technical early access - Secondary Channel Insider), M365 Developer Program sandbox (eligibility includes ISV Success, MAICPP; Cited in prerequisites).
