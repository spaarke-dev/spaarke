## 2026-09-24: Landing external LOB data INTO Dataverse on a schedule

**Question**: For the ontology-platform connection/ingestion layer (Dataverse rows as destination, small volumes, alternate-key upsert, on-prem sources incl. SFTP LEDES drops, customer-tenant + solution ALM), what is Microsoft's current recommended tooling and what are the honest trade-offs?

**Findings** (all Learn pages fetched 2026-09-24):
- **Fabric Data Factory CAN write to Dataverse**: pipeline copy activity (`CommonDataServiceForAppsEntity` sink; `writeBehavior` MUST be `upsert`; `alternateKeyName`; `ignoreNullValues`; `writeBatchSize` default 10) and **Copy job** (Full load / Append / **Upsert**; no watermark incremental when Dataverse is the *source* — irrelevant for destination). Gateway: None / On-premises / VNet; auth: org account / SPN / workspace identity. **Dataflow Gen2 has NO Dataverse destination** (destination list 2026-09-17 excludes it; connector matrix shows Dataverse Gen2 = source only).
- **ADF**: "fully supported... no forced upgrade and no deadline"; innovation goes to Fabric DF (Learn 2026-09-15). ADF→Fabric upgrade experience still **Preview**. ADF Dataverse sink = upsert + alternateKeyName + `bypassBusinessLogicExecution` + `bypassPowerAutomateFlows` (Fabric copy activity page does NOT list the bypass props). ADF mapping data flows add insert/update/upsert/delete + alternate-key lookups.
- **Power Platform standard (V2) dataflows**: solution-aware but **application users (SPNs) cannot deploy dataflows**, no connection references, no environment variables, credentials must be re-entered after EVERY import (update and upgrade), import performs unmanaged customizations, custom tables must be added manually, no preferred-solution support. Upsert = pick alternate key in Map Tables; "Delete rows that no longer exist" relies on createdon/modifiedon. Cannot map Status/Status Reason, polymorphic lookups, multi-level lookups; line breaks stripped. Limits: 24h refresh, 4h/query, 4 concurrent queries; retried 3x on service-protection throttling. Observability = `DataflowRefreshHistory` + `EntityRefreshHistory` managed tables (≥50 refreshes, ~90-day retention). **Contradiction**: differences page (2026-09-03) says Standard V2 "Incremental Refresh policy: Supported"; incremental-refresh page (2025-11-26) says Power Apps incremental refresh "only available for dataflows with ADLS as destination"; solution page says incremental config is dropped on solution deploy. Standard V1 discontinued 2025-05-31; BYOL analytical creation ends 2026-10-31; referenced linked entities disabled 2026-09-01 / stop 2026-10-31.
- **Gen1/Gen2**: Power BI Dataflow Gen1 = "legacy" (blog 2026-04-02, updated 04-20); Pro/PPU path "evolving". Power Platform standard dataflows NOT named in the legacy notice but Learn tips steer everything to Gen2, which cannot write Dataverse → gap.
- **Mirroring / Link to Fabric**: Dataverse→OneLake only; Open Mirroring lands into a Fabric mirrored DB, not Dataverse; Fabric-backed virtual tables are read-only. Nothing writes back into Dataverse rows.
- **Release waves retired** 2026-08-25 (Richard Riley); Release Planner retires 2026-11-15; roadmap → AI at Work roadmap. No 2026 wave 2 plan exists.
- **Dataverse bulk API**: `UpsertMultiple` with alternate keys (`@odata.id` relative URL); standard tables roll back whole batch on error; 100–1,000 rows/req; duplicates in payload error. Power Automate/Logic Apps Dataverse connector has "Upsert a row" but keyed by Row ID GUID in the reference (alternate-key upsert via OData key syntax not documented on that page).
- **Fabric licensing**: pipelines need an F capacity in the *customer* tenant (F2 minimum; Free per-user license suffices for non-Power-BI items). Fabric items are not Dataverse solution components — deploy via Fabric Git/deployment pipelines/REST + Variable library.

**Verdict for Spaarke**: For small volumes, (sourcesystem, sourceid) alternate-key upsert, on-prem SQL + vendor REST + SFTP LEDES, and programmatic per-customer provisioning, the least-friction path is Spaarke-owned code (BFF/Functions worker + `UpsertMultiple`, Service Bus scheduling, change-tracking watermarks, own run ledger); gateway/on-prem reach via Azure Relay / customer-side agent or the on-premises data gateway only if a Microsoft pipeline is used. Fabric Copy job is the best *Microsoft-native* option if customers accept an F SKU; standard dataflows are viable only with manual post-import credential steps.
