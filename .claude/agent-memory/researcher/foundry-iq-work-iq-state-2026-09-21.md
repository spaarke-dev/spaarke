# Foundry IQ + Work IQ state (2026-09-21)

**Question**: Current (Sept 2026) state of Foundry IQ knowledge bases and Work IQ vs a hand-built .NET BFF hybrid-RAG over 7 push-indexed AI Search indexes (3072-dim, HNSW, semantic reranker, tenantId + Entra-group string filter, AOAI-only).

## Foundry IQ — key facts
- **GA = `2026-04-01` REST** (Learn whats-new, April 2026): KBs + `searchIndex`/`azureBlob`/`indexedOneLake`/`web` KS types GA, **but GA = minimal/extractive only** — NO query planning, answer synthesis, reasoning effort, retrievalInstructions, or `models` for non-web KS. Full features need `2026-08-01-preview` (Aug 2026; `2026-05-01-preview` June 2026). Foundry blog (2026-06-02) also claims "Foundry IQ MCP server GA" but Learn wires the MCP endpoint only via `2026-08-01-preview` and calls the `RemoteTool` connection "(preview)" → contradiction.
- **BYO index works**: `searchIndex` KS wraps an existing index on the SAME service; needs searchable+retrievable strings, semantic config (optional from 2026-05-01-preview), vectorizer on the vector field for vector subqueries. Scoring profiles NOT honored. `baseFilter` (persisted) + `filterAddOn` (per-request, AND-only) preview → you CAN pass your own tenant/group string filter. `queryHints` (preview) = model-generated filters/boosts, best-effort only.
- **Planner = Azure OpenAI only** (`models[].kind: azureOpenAI`; gpt-5.x incl 5.5/5.6 on 2026-08-01-preview; GPT-4 family deprecated). No non-AOAI provider documented. `retrievalReasoningEffort: auto` new (Aug 2026).
- **Permissions**: native path = `x-ms-query-source-authorization` = USER token for `https://search.azure.com/.default` (OBO ok; app-only NOT supported); service extracts `oid`, resolves groups transitively via Graph, matches `userIds`/`groupIds` (Entra GUIDs) permission-filter fields; caller cannot inject its own group list; Graph failure → 5xx fail-closed; SP-group-in-Entra-group nesting not expanded; Purview label enforcement single-tenant only. All preview. "Security filters" (string compare) remain the GA, API-agnostic alternative = what Spaarke does today.
- **SPE**: NO SPE KS kind. Path = `remoteSharePoint` KS (preview) with `remoteSharePointParameters.containerTypeId` → Copilot Retrieval API `sharePointEmbedded` data source (beta/preview). Requires: search service + M365 in the SAME Entra tenant; PAYG billing on container type; ≥1 Copilot-licensed user in tenant (semantic index init); container-type discoverability; grant Foundry app `880da380-985e-4198-81b9-e05b1cc53158` `readContent` per consuming tenant; delegated only; 25 results/200 req/user/hr; one remote query at a time per replica; billed on Copilot Studio message meter (private preview meter). Old SPE ChatEmbedded SDK deprecated Mar 2026.
- **Billing**: AI Search `knowledgeRetrieval` plan split from `semanticSearch` (2026-04-01); free plan default (50M tokens/mo per pricing page), standard ~$0.022/1M reranking tokens (Basic+); AOAI planner tokens billed separately; Serverless (preview) billing began **2026-09-13**.
- **Does NOT do**: no confidence beyond `rerankerScore`; no groundedness/citation verification; no evidence-sufficiency refusal (refusal is agent-prompt only); no fact-vs-inference classification. Purely retrieval + optional synthesis.

## Work IQ — key facts
- **GA 2026-06-16** for API endpoints: A2A (`workiq.svc.cloud.microsoft/a2a/`), remote MCP (`workiq.svc.cloud.microsoft/mcp`, 10 tools: fetch, fetch_blob, create_entity, update_entity, delete_entity, do_action, call_function, ask, list_agents, get_schema, search_paths — doc says 10, lists 11), REST (chat). "Context" and "Workspaces" are pillars in the overview/blog; **no Learn endpoint page exists** for either (404). Consumption surfaces are preview: Foundry `work_iq_preview` tool (A2A+OBO), Copilot Studio "Work IQ (preview)", AI Search `workIQ` KS (preview, customer-owned app + FIC OBO, `x-ms-query-work-iq-source-authorization`, 40–60 s latency).
- **Auth**: delegated only, OBO supported, app-only explicitly NOT supported (permissions page + api-overview + Foundry tool page). Scope `api://workiq.svc.cloud.microsoft/WorkIQAgent.Ask`, admin consent required. Multitenant ISV: register app `AzureADMultipleOrgs`, token `iss` must be user's home tenant; customer needs Work IQ SP provisioned (app `fdcc1f02-…`), admin consent, Copilot-Credits spending policy incl. the user. MCP mutations blocked by default (tenant policy).
- **Metering**: Copilot Credits, independent of M365 Copilot seat; Tools API 0.1 credit/call fixed, Chat/Context variable (MS licensing news 2026-06-02); $0.01/credit is third-party reported only. Managed in M365 admin center Cost management (Work IQ needs its own spending policy).
- Stale-doc trap: Foundry MCP quickstart (2026-06-23) and Foundry IQ FAQ (2026-05-13) still say per-user Copilot license required — superseded by usage-based billing / PAYG pages.
- **Dataverse in Work IQ** (2026 wave 1): "Chat and reason over Dataverse data in M365 Copilot" preview 2026-06-22 (no GA); Dataverse skills for coding agents preview 2026-06-01; Dataverse MCP tool update GA 2026-06-08; agent users w/ Entra agent identity GA Aug 2026. Release plans discontinued Sept 2026 → AI at Work roadmap.

## Judgment delivered
Foundry IQ could replace Spaarke's query-time fan-out/rerank/merge (and add LLM query planning + `auto` effort) over the EXISTING indexes without re-ingestion, but it does NOT replace ingestion (SPE→chunk→embed→push), does not do epistemic/confidence/refusal, keeps AOAI-only, and its native permission trimming is preview + Graph-resolved (Spaarke's string filter maps to preview `filterAddOn`). SPE-as-remote-KS is a non-starter for the ISV multi-tenant stamp (same-tenant + Copilot-license/PAYG + delegated-only). Work IQ not adoptable for app-only/background paths; only as a delegated collab-context tool.
