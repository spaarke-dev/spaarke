# Microsoft platform scan for the Spaarke authority model — 2026-09-21

**Question**: For spaarke-ontology-platform-r1's authority model (actor = human OR agent; decision-type × value threshold × time-boxed delegation; immutable basis record), what does Microsoft now ship that we should adopt vs build vs ignore? Seven topics: Entra Agent ID for Dataverse, Agent 365, Dataverse MCP, Agent Framework 1.0, Dataverse audit/change-tracking/LTR, Legal Agent for Word, ontology-adjacent Dataverse/Power Platform features.

## Findings (dated)

- **Entra Agent ID for Dataverse = PREVIEW, not GA** (blog 2026-08-06; Learn `create-users` "Agent users (preview)" updated 2026-08-14; release plan said GA Aug 2026 but NOT checkmarked as of 2026-08-27). It gives an agent identity → Dataverse `systemuser` of a new type (PPAC Users+permissions > **Agents** > Add agent) + ordinary security roles + audit attribution. NO conditional/delegated/value/time authority — the Dataverse layer is identity + role only. Entra's own token model (`agent-tokens`, updated 2026-08-14) does support user-delegation (OBO with blueprint audience, `xms_act_fct`/`xms_sub_fct` claims) and agent-user-account impersonation, but that is OAuth-scope delegation, not business-rule authority. Release plan says "autonomously or on behalf of users" — no doc shows how on-behalf-of surfaces in Dataverse agent users.
- **Agent 365 = GA 2026-05-01, $15/user/mo (annual), E7 $99/user/mo; per-USER not per-agent; E5 (or Business Premium / Defender+Purview suite) prerequisite.** Registry converged into M365 admin center (Entra keeps identity). ISV path: create agent identity blueprint → register agent card via SDK/CLI (`a365 setup all`) or Agent Registry API; partner "ready-to-deploy" agents listed on Learn `third-party-agents`. NO evidence that registration is a hard requirement for an ISV agent to run; it IS the way to appear in the customer's registry and avoid the "Unmanaged agents" bucket — soft procurement pressure, not a gate. AI Reader role sees inventory without license; governance controls need Agent 365 license.
- **Dataverse MCP `/api/mcp` = GA** (Learn ms.date 2026-06-05; tool-shape blog 2026-06-08 GA per release plan). 15 tools (search_data, search, create/update/delete_record, create/update/delete_table, read_query, describe, upsert_skill, delete_skill, init/commit_file_upload, file_download). Clients: Copilot Studio, VS Code Copilot, Copilot CLI, Claude desktop/Code, any MCP client. Delegated user context only (security roles honoured); metered from 2025-12-15 for agents outside Copilot Studio. **Custom tools**: NOT on `/api/mcp`; the PREVIEW "MCP management MCP server" (`MCPManagement`, Copilot Studio docs ms.date 2026-06-02) lets you create an environment MCP server and add tools from Dataverse **custom APIs**, SDK messages, connectors, Graph, remote APIs; "Bring Your Own MCP" + MCP Certification GA per July-2026 Dataverse blog. Separate Frontier-only Agent 365 Dataverse MCP still shows the OLD tool shape (describe_table/list_tables/fetch).
- **Agent Framework .NET 1.0.0 GA 2026-04-02** (tag), blog 2026-04-03. rc1 2026-02-20 → rc2/3/4/5 → GA. Breaking changes since rc1: StateBag/multi-provider composition, structured-output changes, WorkflowOutputEvent unification, polymorphic routing, checkpointing decoupled (rc1); ChatClient decorator for AIContextProviders (rc2); provider StateKeys list + response filter (rc3); rc5: type/source-generator renames, skills multi-source, Foundry→Responses API, checkpoint-store sessionId fix; GA: `ServiceStoredSimulatingChatClient`→`PerServiceCallChatHistoryPersistingChatClient`, `Microsoft.Agents.AI.AzureAI`→`.Foundry`, OpenAIAssistantClientExtensions removed. Post-GA still breaks monthly: 1.18 (AgentIsolationKeyProvider), 1.19 (MCP Tasks 2026-07-28), 1.21, 1.22 (2026-09-18: Approval Binding replay, per-invocation MCP sessions, sticky Foundry delegated identity on AgentSession). SK: "maintenance, critical fixes ≥1yr post-GA" is secondary-source only; no primary Microsoft statement located.
- **Dataverse audit**: field-level old/new via RetrieveRecordChangeHistory/RetrieveAttributeChangeHistory/RetrieveAuditDetails (prvReadRecordAuditHistory+prvReadAuditSummary); Web API RetrieveRecordChangeHistory omits AuditRecord (no who/when) — use SDK or query `audit` table; values >5KB truncated; audit table = 1 link-entity max, no joins beyond systemuser; not on TDS; retention default Forever / max 24,855 days; logs in Log capacity (AuditBase, PlugInTraceLogBase, Elastic tables), Database capacity can cover Log overage but not vice-versa; delete ~100M rows/day. Change tracking = delta token (7-day default `ExpireChangeTrackingInDays`), record-level, no old values, org-level read required, no $filter/$top. LTR = FetchXML `datasource="retained"` only (no OData), 5 concurrent users / 100 queries/day, Managed Env, moves rows OUT of transactional DB. Backups 7d (28d prod managed), whole-environment restore only. Recycle bin GA 2026-04-27 (1–30 days, delete-only). **NO as-of / point-in-time / bitemporal query exists.**
- **Legal Agent for Word (2026-09-21)**: Frontier preview only (US late-Apr 2026, worldwide Frontier mid-Jun 2026); MC1388706 updated 2026-08-24 → GA "early October 2026" (slipped from early September). Desktop Word (Windows) ≥2604; playbook = local .docx upload (converted to "skills") + SharePoint per support article; NO DMS/iManage/NetDocuments/MCP ingestion in Microsoft docs (techjacksolutions "Enterprise GA May 3 + iManage MCP" is trade-press, contradicts MC — treat as unverified). Tracked-changes redlines confirmed in MC + support doc.
- **Ontology-adjacent**: (1) **Dataverse semantic model (preview)** Learn ms.date 2026-06-17 — auto-provisioned when Dataverse Intelligence on; data scope + inferred signals (relationships/views/forms/descriptions) + human glossary; consumed by Copilot in Power Apps, M365 Copilot with Dataverse, Sales Agent, Copilot Studio; no API, no ALM, cannot create new model, not consumed by /api/mcp per docs. (2) **Fabric IQ Ontology (preview)** — entity types/properties/relationships/graph/NL2Ontology; binds ONLY OneLake (managed lakehouse tables, eventhouse, PBI semantic models) — NO direct Dataverse binding (needs Link to Fabric); exposed via `mcp_FabricIQOntology` (2 tools: list_ontology_entity_types, search_ontology), Copilot Studio preview, needs F2+ capacity. Fabric IQ GA at Build 2026 but Ontology item still preview (Learn overview updated 2026-08-28). (3) Nothing for authority/permission semantics; no "business concepts" product beyond CDM. Release plans END Sept 2026 → AI at Work roadmap.

## Judgment delivered
Adopt: Entra Agent ID + Dataverse agent user as the agent principal (identity layer), Dataverse audit on authority tables, Agent Framework (already), MCP-shaped contracts. Build: authority decision model (actor × decision type × threshold × delegation window), immutable basis ledger (append-only Dataverse table or SPE, audit as corroboration not primary), as-of evaluation, delegation semantics. Ignore for now: Agent 365 registration (unless customers demand), Fabric IQ ontology, Legal Agent (competitor/complement signal only), Dataverse semantic model as an authority substrate.
