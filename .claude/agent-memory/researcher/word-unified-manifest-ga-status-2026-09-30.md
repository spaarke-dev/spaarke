# Word unified manifest GA status (2026-09-30)

**Question**: Is the unified JSON manifest production-ready for Spaarke's Word add-in (FR-05 "migrate Word to JSON"), and how to test it without breaking the live XML install?

**Findings**:
- GA for Word/Excel/PPT announced devblog 2026-07-16/17. Learn unified-manifest-overview (ms.date 2026-09-24) platform table: web Yes; Word Win **2501 (18407.20002)+ M365 subscription**; Word Mac **16.103+**; perpetual Win / mobile / iPad = No. Only Word/Excel/PPT gap listed: **OnDocumentOpened** event. Sideload page still says Win 2304+ (older floor; conflict).
- Latest GA schema **1.30** (Aug 2026). Convert doc says use latest released OR devPreview; devPreview reportedly rejected by Admin Center / Dev Portal validation (Q&A 5934110, vendor moderator, 2026-06-30 — medium confidence). Ship on 1.30.
- Integrated apps: upload unified add-in as **App type = "Teams app"** + zip package (not "Office Add-in"). publish.md: internal (LOB) unified add-in won't install on unsupported Office versions; duplicate-add-ins page says admin "deploy for all users" exception lets older/perpetual install — the two pages conflict.
- Coexistence: MS says the unified version MUST use a **different GUID** from the XML `<Id>` (convert doc step: "Change <ID> to a new random GUID"), different name + icons, and `extensions.alternates[].hide.customOfficeAddin.officeAddinId` = old XML id; takes up to 24 h, both UIs visible meanwhile. Don't remove the XML from admin center. Max **20 add-in commands**; FunctionName <65 chars.
- Spaarke repo state (2026-09-30) — ⚠️ **CORRECTED TWICE by the main session; this version is verified.** **PRODUCTION RUNS XML FOR BOTH HOSTS**: Outlook = `outlook/outlook-manifest.xml` (`<Id>5e4d66d0-2603-44ea-acbc-400d3b881c90</Id>`, v1.0.22.0), Word = `word/word-manifest.xml` (`<Id>b3965ea0-6942-4f17-81b3-2c645bd05ebf</Id>`, v1.0.9.0). The two JSON manifests were **dev-sideload only**. TRAP (already recorded by this project, then walked into anyway): Outlook's production XML is `/outlook/outlook-manifest.xml`, NOT `/outlook/manifest.xml` (that one 404s) — probing the wrong path made the first correction wrongly claim Outlook ran unified JSON. Also verified against the BUILT artifact, not `src/`: webpack rewrote each JSON's top-level `id` AND `webApplicationInfo.id` to `ADDIN_CLIENT_ID` (`c1258e2d-…`), so both dev JSON manifests shared ONE package id — a real conflation, but not a threat to any live app (`c1258e2d` is no production app's id). The built JSON has no localhost URLs; Word JSON and XML declare identical requirement sets. **RESOLVED by task 078**: one combined 1.30 package (`packaging/mergeUnifiedManifest.js`) with its OWN id `e68f3cb1-…`, Entra id in `webApplicationInfo.id` only, `alternates.hide` naming BOTH XML ids. LESSON: inspect the built/deployed file, and check the project's own notes for a known trap before concluding from a 404.

- **Follow-up (same day) — multi-host Outlook+Word shape**: Schema ref element-extensions (2026-08-11) says "Each app supports only one extension" → combine hosts via ONE extension object with `requirements.scopes` listing any subset of mail/workbook/document/presentation (specify-office-hosts-unified, 2026-09-10); filter runtimes/ribbons/alternates per host with nested `requirements.scopes`. No current Learn text forbids mail+document; GA blog cites Script Lab Unity (Outlook+W/X/P merged into one app). Only hard exclusion: content add-ins (contentRuntimes) can't combine. Per-host floors still apply (Outlook Mac = unsupported at all). `prefer` only covers comAddin/XLL; `hide.customOfficeAddin.officeAddinId` = XML `<Id>` is the right element BUT **open bug office-js #6938 (2026-09-10): hide.customOfficeAddin works for Outlook, NOT Word/Excel/PPT** (desktop+web, CD+sideload) → both ribbons show. NAA: one Entra registration, `brk-multihub` covers Word+Outlook+Excel+PPT+Teams; root `id` doc = just "unique GUID", webApplicationInfo.id = "AAD application id" — no rule forbidding equality (undocumented). Live Outlook package is devPreview and centrally deployed → counter-evidence to the Q&A "devPreview rejected" claim.

- **Permissions + validDomains (same day)**: XML→unified mapping VERIFIED: `ReadWriteDocument` → `Document.ReadWrite.User` (requesting-permissions page, 2026-06-30); `ReadWriteItem` → `MailboxItem.ReadWrite.User` (understanding-outlook-add-in-permissions, 2025-12-02); both `"type":"Delegated"`. Converter `office-addin-manifest-converter` 0.4.1 emits exactly these. `resourceSpecific` is root-level (app-wide); no doc on mixing mail+document entries — but the bundled Office parser (osfmos.js) for task-pane apps switch-matches only `Document.*` names and silently ignores others (inference: each host picks its own family). validDomains: converter copies `<AppDomain>` strings VERBATIM (so `https://login.microsoftonline.com` stays scheme-qualified); official samples mostly use `https://origin`, one uses bare `contoso.com`; schema text is Teams-oriented, format unspecified. Own start-page origin need not be listed (overview "Specify safe domains"), harmless to include.
