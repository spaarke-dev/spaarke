## Interpretation

- **§R5 verified for the THIRD time** — topology doc §7 verified twice on 2026-08-28 (sdap-SPE-admin-app-r2 project). We verified again 2026-08-30 from the r1 worktree. Any doubt about §R5 being universally applicable to `client_credentials` grant against `/containerTypes` (regardless of credential shape) is now empirically closed.

- **Grant-type is what matters**, not credential shape — Microsoft OAuth semantics treat `client_credentials` as an app-only flow whether the credential is a secret, certificate, or federated identity. §R5's "delegated-only" applies to ALL `client_credentials` variants. H8's `ClientCertificateCredential` therefore inherits the same 403 as the sibling probe's `client_secret` — the credential SHAPE doesn't matter; the OAuth GRANT TYPE does.

- **H8 was never live-tested end-to-end in dev** — confirmed by TWO independent findings:
  1. Cert drift (KV cert not registered on owning app-reg) means token acquisition itself would have failed at the very first live invocation. If H8 had EVER been run against a real Graph call in dev, the drift would have been noticed + fixed.
  2. Even fixing the cert drift and re-running would 403 per §R5. H8 has ALWAYS been broken by design since task 051 (2026-06) baseline, preserved through task 131 (2026-08) Wave G-3 Graph SDK port.

- **Topology doc §8.1 was correct** — "Handler H8 of the provisioning flow inherits this defect and should be treated as unproven."
