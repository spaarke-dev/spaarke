## Overview

The Spaarke DataGrid framework (R1) shipped `<DataGrid configId=... />` as the canonical shared-lib grid, driven by `sprk_gridconfiguration` records. Production use in `ai-spaarke-ai-workspace-UI-r2` surfaced 11 gaps — the load-bearing one is a broken height chain that causes multi-section workspace grids to grow unbounded instead of scrolling. R2 delivers additive framework capabilities (no `_version` bump), unwinds a tactical CSS hack from 6 section registrations, and extracts LegalWorkspace's section registry into a proper shared package so SpaarkeAi no longer aliases into a sibling workspace's source tree.

**Ships as 3 phased PRs across 4 project phases. Total estimated effort: ~3.5 days.**

## Purpose

Solve 11 gaps from R1 production use — one load-bearing (height chain), plus configuration-layer maker experience, per-instance flexibility, framework hygiene, and one operational trap (SpaarkeAi build-time alias to LegalWorkspace source).

## Proposed Solution

**Additive schema evolution** — no `sprk_configjson` `_version` bump. New fields default to backward-compat behavior when omitted. Framework changes stay in `@spaarke/ui-components`. Wizard UI additions to `WorkspaceLayoutWizard` code page. New shared package extracts LegalWorkspace's section registry so all consumers (LegalWorkspace + SpaarkeAi + WorkspaceLayoutWizard) build against a single library.

## Scope

### In Scope (10 FRs)

- **FR-01** Framework `contentSizing: 'grow' | 'clamped'` on `SectionMetadata` (load-bearing height-chain fix)
- **FR-02** Per-row `rowHeight` in `LayoutJsonRow` + wizard UI
- **FR-03** `SectionInstance` schema for per-instance `configId`/`label`/behavior overrides + wizard "Advanced" panel (folds Issue 6 rename)
- **FR-04** `widthPreference: 'full' | 'half' | 'any'` on `SectionMetadata` + wizard placement checks
- **FR-05** `availableViews` allowlist on `SourceSavedQuery`
- **FR-06** Three DataGrid config templates in `scripts/config-templates/`
- **FR-07** Framework `pageSize` default → **25** (owner-clarified 2026-07-02, was 100)
- **FR-08** Unwind tactical `maxHeight` hack from 6 entity-list registrations
- **FR-09** Dual-deploy warning in `code-page-deploy` skill + widget-authoring guide
- **FR-10** Extract LegalWorkspace section registry into new shared package (adopted 2026-07-02 per owner clarification)

### Out of Scope

- Editable-cells feature (separate future project)
- Server-side aggregations
- Legacy `IGridConfigJson` consumer retirement (R1 backlog)
- Any `_version` bump — additive fields only
- Any BFF endpoint / service / DI change (hot-path BFF=N)
- Hiding the DataGrid scrollbar (Issue 10 — deferred by decision)

## Who Benefits

- **Makers** — better authoring experience (templates, view allowlist, per-layout overrides, wizard warnings)
- **End users** — correctly-scrolling grids in multi-section dashboards; no more "50 rows visible, no scrollbar" surprise; full-page layouts use the whole tab

- **Future consumers** — new workspace-hosting code pages (Compose, Insights Engine widgets, action-engine surfaces) inherit the section registry via a normal shared-package dependency
