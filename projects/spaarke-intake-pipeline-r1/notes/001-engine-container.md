## Contracts used

**Engine CLI** (master, unchanged): table under "Engine CLI contract found on master" below. Sequence per `run_local_e2e.py`.

**Operations** (one envelope field `payload.operation`, closed set; anything else → dead-letter `InvalidFormat`, `unknown_operation`):
- `segment`: `segment_clauses.py source.docx` → `clauses.json`. Completion carries ids and outcome only (`completed` / `input_invalid`).
- `redline`: dry-run → redline (internal, external, clean) → summary (`--intro`) → check. Outputs `redline-internal.docx`, `redline-external.docx`, `clean.docx`, `check-report.json`.

**Staging paths** (container `INTAKE_STAGING_CONTAINER`): source `{runId}/in/source.docx`; plan `{runId}/in/redline/{dispatchAttempt}/plan.json`; outputs `{runId}/out/{operation}/{dispatchAttempt}/{name}`; marker `{runId}/markers/{operation}/{dispatchAttempt}.json`.

**Idempotency key:** `IntakeEngine:{runId}:{operation}:{dispatchAttempt}` (GUID canonical lowercase). **Reconcile with task 014**, whose POML says `IntakeEngine:{runId}:{dispatchAttempt}`: the operation is in the key because one run dispatches `segment` and then `redline` under the same dispatch attempt; without it the second would be a duplicate. 014 must build the same key and paths.

**Completion** (to `INTAKE_COMPLETION_QUEUE` only): `message_id` = request idempotencyKey, `correlation_id`, `application/json`, subject `IntakeEngineCompleted`; body = Job Contract (camelCase), payload `{operation, runId, dispatchAttempt, outcome, checkOutcome, refusedEdits:[{edit,code}], refusedBookmarks:[{bookmark,code}]}`. No paths, no content. `operation` and the refusal lists are beyond the POML's list; the first is needed by the `segment` amendment, the second by the owner's "refused edit index + reason code".

**Outcomes:** `completed`; `plan_does_not_fit` (exit 3; non-retryable; nothing uploaded); `input_invalid` (exit 2; non-retryable); `contract_error` (engine output breaks its contract, or an unknown skip-report code → dead-letter `Poisoned`). Retryable (timeout, kill, other exit codes, storage/marker errors) → scheduled copy with `PriorDeliveryCount`, `JobContract.RetryDelay` (1/2/4/8 min), DLQ `MaxRetriesExceeded` at logical delivery 5; unexpected exceptions → `ProcessingError` path. Invalid envelope → `InvalidFormat`.

**Refusal codes:** default mode reads `{"code","edit"|"bookmark"}` from the last stderr line when present (the shape PR #3237 put on master as 244171569a; `"error"` is never read into anything that is logged), else maps master's `edit N: …` messages onto the accelerator's closed set; no edit prefix → `plan_invalid`, garbage → `unrecognised`. Stderr is never logged, raised or sent.

**Skip-and-report (seam, OFF):** `INTAKE_ENGINE_SKIP_AND_REPORT` (default false). When on: `--skip-unplaceable refused-report.json` on the redline, `--refused` to summary and check, the report is validated strictly (closed code set; any deviation → `contract_error`) and uploaded as `refused-report.json` beside the outputs; the completion carries the refused codes. `main` refuses to start (exit 2) if the flag is on and the engines' `--help` lacks the flags.

### The divergence

The task assumed (FR-01g; spec FR-09(b)): *"An edit whose anchor is not unique or crosses an existing revision is listed in the check report and not applied."*

On master, `ooxml_redline.run()` is **all-or-nothing**: the first edit that does not fit raises `PlanError`, the process exits 3, and **no output file is written**. There is no skip mode, `check_outputs` has no refused-edit check, and `summary_table` has no "manual" row type.

Probe (synthetic nda-01 + golden plan + one non-unique `find`): exit 3, stderr `{"error": "edit 19: find 'the' occurs 5 times in the visible paragraph text"}`, zero `.docx` written.

ADR-015: `PlanError` text quotes up to 50 characters of plan/clause text (`needle[:50]!r`), so the wrapper never logs or forwards engine stderr; it reports only the edit index and a code.

## Skip-and-report mode: accelerator contract (2026-11-26; implemented as an OFF option)

- `ooxml_redline.py PLAN DOCX REDLINE [--external EXT] [--clean CLEAN] [--dry-run] --skip-unplaceable REPORT.json`. Each edit is tried alone; a refused edit leaves nothing partial. Exit codes in this mode: 0 = outputs written (even if every edit was refused), 2 = bad input, 3 = the plan breaks the contract (`validate_plan`). stdout gains `"refused": <count>`.
- REPORT.json is codes only: `{"engine":"ooxml_redline","report_version":1,"edits_total":N,"edits_applied":N,"refused":[{"edit":<0-based>,"code":"..."}],"bookmarks_refused":[{"bookmark":"NDA_Sec10","code":"..."}]}`.
- Closed code set: `para_not_found`, `para_not_unique`, `not_found`, `not_unique`, `in_existing_markup`, `word_boundary`, `old_not_in_find`, `crosses_markup`, `crosses_field_or_drawing`, `in_field_result`, `nothing_after_heading`, `bookmark_exists`.
- `summary_table.py ... --refused REPORT.json` adds "by hand" rows; `check_outputs.py ... --refused REPORT.json` validates the report.
- Default-mode reason codes reuse this set; fallbacks `plan_invalid` / `unrecognised`.

## Escalation 2 (2026-11-26): `.docx` outputs are not byte-reproducible — resolved

- Cause (engine code): `ooxml_redline.py:593-596` and `summary_table.py:276-278` write parts with `zipfile.ZipFile.writestr(<str name>, data)`, which stamps local wall-clock time on every entry.
- Evidence: two `run_local_e2e.py` runs (07:14 and 07:31) differ by whole-file sha256 on all 9 `.docx`; per member, content bytes and CRC-32 are identical, only `date_time` differs. Plan JSON and the `check_outputs` report are byte-identical.
- Owner decision: the accelerator writes fixed `ZipInfo` dates; until that is on master, parity = same part names + identical bytes and CRC-32 per part + whole-file check report, behind one switch (`DOCX_IDENTITY`). Rejected: a faked clock, a monkeypatched `zipfile`, rewriting outputs.
