## Key Technical Constraints

### MUST Rules

- ✅ **MUST** use `Xrm.WebApi` for all Dataverse reads/writes — per ADR-028 boundary + spec NFR-05
- ✅ **MUST** use Fluent v9 semantic tokens exclusively — per ADR-021 + spec NFR-03
- ✅ **MUST** keep shared components React 16/17-compatible — per ADR-022 + spec NFR-06
- ✅ **MUST** honor Notepad launch contract (`regardingEntity`, `regardingId`) as external API surface — per spec NFR-09
- ✅ **MUST** render sparkle refresh icon as unwired in R1 — per spec FR-08a (NEVER add BFF endpoint to support it)

### MUST NOT Rules

- ❌ **MUST NOT** add any endpoint, service, or DI registration to `src/server/api/Sprk.Bff.Api/**` — spec NFR-07
- ❌ **MUST NOT** import `@spaarke/auth` — spec NFR-05 (host-context surface only)
- ❌ **MUST NOT** modify `src/client/pcf/VisualHost/**` — CardChrome migration is follow-on
- ❌ **MUST NOT** modify `src/solutions/EventDetailSidePane/**` — MemoSection adoption is follow-on
- ❌ **MUST NOT** re-implement toolbar wiring inside per-entity PCFs — MUST use `useRecordHeaderToolbarActions`
- ❌ **MUST NOT** add new NuGet or npm packages beyond existing baseline — spec NFR-08
- ❌ **MUST NOT** use React 18-exclusive APIs in shared components consumed by PCFs

### ADR Tension in Effect (per CLAUDE.md §6.5)

**ADR-024 Path A exception**: `sprk_memo` uses text field `sprk_regardingrecordid` (GUID-only string) rather than participating in the 11-entity polymorphic `regardingobjectid` lookup. This is a pre-existing schema decision of the `sprk_memo` entity — not introduced by this project — but it means R1 code queries and creates memos in a non-standard way. Consequences: no Dataverse-enforced referential integrity between memos and their regarding record (no cascade delete). Application-level linkage only. See spec.md "ADR Tensions" section for full rationale.
