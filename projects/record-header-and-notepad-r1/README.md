## Overview

This project replaces the OOB record-header on the Matter main form with a compact 5-field summary card plus a three-action toolbar (AI summary popover, related to-dos, Notepad). It ships reusable primitives in `@spaarke/ui-components` (`HeaderToolbar`, `RecordHeaderShell`, `FieldGrid`, field renderers, and a shared `useRecordHeaderToolbarActions` hook) plus a standalone entity-agnostic Notepad code page, so v2+ per-entity thin PCFs (`ProjectHeaderPcf`, `InvoiceHeaderPcf`, …) can each be added in ~80 LOC.

**v1 ships Matter.** Each follow-on entity gets its own ~80 LOC thin PCF composing the same shared primitives.

## Problem Statement

Today the Matter form's header shows platform-default OOB field cells with three unrelated user actions scattered across the form and ribbon: (1) opening the AI-generated `sprk_recordsummary` for the record, (2) viewing related to-dos, and (3) taking unstructured notes about the record. Users have no consistent access point for these actions, no way to preview summaries inline, and no first-class "notepad" experience. The lack of a shared record-header primitive means every future entity that needs a compact 5-field summary + action toolbar (Project, Invoice, Event, …) will re-implement card chrome, grid layout, and action wiring from scratch — the exact anti-pattern CLAUDE.md §11 catches.

## Solution Summary

Ship reusable primitives once (`HeaderToolbar`, `RecordHeaderShell`, `FieldGrid`, field renderers, `useRecordFieldValues`, `useRelatedCount`, `useRecordHeaderToolbarActions`) in `@spaarke/ui-components`, then compose them in a thin per-entity PCF (`MatterHeaderPcf` v1 at ~80 LOC). Add a standalone entity-agnostic Notepad code page that any Spaarke surface can launch via a stable URL contract (`?regardingEntity=X&regardingId=Y`). Sparkle click opens an inline popover (not modal) with the AI summary body and a rendered-but-unwired refresh icon (BFF endpoint deferred to a follow-on). Zero BFF surface added in R1; all Dataverse I/O via `Xrm.WebApi`.

Toolbar actions:

- **Sparkle** → Fluent v9 popover with `sprk_recordsummary` body + refresh icon (unwired in R1)
- **Checkmark** → SmartTodo code page at 85%×85% (Layout 1), with live `sprk_todo` badge count
- **Annotation** → Notepad code page at 70%×80%, with live `sprk_memo` badge count

## Key Decisions

| Decision | Rationale | ADR |
|----------|-----------|-----|
| Per-entity thin PCFs (not one PCF with `variant`/JSON schema) | Self-documenting manifest names; native typed JSX; per-entity release-risk decoupling; ~30 LOC one-time cost | [ADR-006](../../.claude/adr/ADR-006-prefer-pcf-over-webresources.md), [ADR-011](../../.claude/adr/ADR-011-dataset-pcf-over-subgrids.md) |
| Shared primitives + shared toolbar-actions hook in `@spaarke/ui-components` | Three toolbar actions are 100% invariant across entities; extract once | [ADR-012](../../.claude/adr/ADR-012-shared-component-library.md) |
| Sparkle opens Fluent v9 popover (not modal) with refresh icon | Owner clarification O2 — inline preview + refresh entry point for future BFF endpoint | — |
| Refresh icon rendered but not wired in R1 | Owner clarification O2a — preserves NFR-07; follow-on project wires the endpoint | — |
| Matter form binding is a follow-on maker task | Owner clarification O3 | — |
| `sprk_memo` uses text field `sprk_regardingrecordid` | Pre-existing schema; Path A exception to ADR-024 | [ADR-024](../../.claude/adr/ADR-024-polymorphic-resolver-pattern.md) |
| All Dataverse I/O via `Xrm.WebApi` (no BFF) | No cross-cutting logic; `Xrm.WebApi` ~20-50ms vs BFF ~100-300ms | [ADR-028](../../.claude/adr/ADR-028-spaarke-auth-architecture.md) |
| Fluent v9 semantic tokens exclusively; zero hex/rgb | Binding | [ADR-021](../../.claude/adr/ADR-021-fluent-ui-design-system.md) |
| Shared components React 16/17-compatible; Notepad SPA can use React 18 | PCF platform lib boundary | [ADR-022](../../.claude/adr/ADR-022-pcf-platform-libraries.md) |

## Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| `sprk_memo` schema differs from assumption (e.g. `sprk_body` field type/size) | Med | Low | Phase 1 discovery task inspects entity metadata and `MemoSection.tsx` |
