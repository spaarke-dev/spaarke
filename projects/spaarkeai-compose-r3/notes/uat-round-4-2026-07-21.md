## Design note — Track Changes (item 4) is a DECORATION, not marks
Marks would be stripped by `rejectStateText` → never persist. The decoration overlay leaves content = real edits, which persist via the already-deployed FR-02 synthesizer. So NO new save path was needed and there's zero corruption risk. Known MVP edges (fast-follow if UAT wants): live per-change accept/reject of user edits; type-over-selection shows the new text as inserted but not the replaced text as struck; running the overlay on a doc that also has pending AI redlines double-counts visually.
