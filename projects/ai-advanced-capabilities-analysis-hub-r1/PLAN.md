## Key Design Decisions

1. **Storage model (locked, ADR-040 Path A)** — Cosmos = durable transcript store-of-record; Dataverse (`sprk_analysis`/`sprk_analysisoutput`) = business anchor + structured deliverables. Per-message Dataverse cold persistence deferred.
2. **Session path** — standardize on `ChatEndpoints` (Redis 24h → Cosmos → Dataverse anchor). Retire `AnalysisEndpoints` legacy in-memory `/continue`+`/resume` + `sprk_chathistory` read + dead `sprk_analysischatmessage`.
3. **Session↔Analysis binding** — new owner-created `sprk_aichatsummary → sprk_analysis` lookup FK; "one Analysis → many sessions" via `sprk_sessionid` grouping + analysis FK.
4. **Fork-on-analysis = new BFF endpoint (UQ-1 → Option B, pending owner confirm)** — `POST /api/ai/analysis/fork` composes create+mint+bind+archive atomically; reuses server-owned services; ADR-013/§10 → Path A exception. *(Archive semantics: accept Cosmos/Redis-authoritative OR implement summary-GUID caching — scoped as a task.)*
5. **Regarding** — RegardingResolver field-set (`sprk_regardingmatter/project/document`), single-valued; KEEP `sprk_documentid` as SPE subject-pointer (separate role from `sprk_regardingdocument`).
6. **Entry** — record-driven opens via `openSpaarkeAi` deep-link, NOT `surfaceLaunchRegistry` (ADR-039 / §13.3). In-chat proactive offer deferred (UQ-4 = NO).
7. **Retirement** — clean (no capability migration, §13.6); `SourceViewerPanel` retired not migrated; ordered per §13.5 (repoint before delete).
