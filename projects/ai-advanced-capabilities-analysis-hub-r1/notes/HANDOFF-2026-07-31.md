## 4. ⭐ EXECUTION-MACHINERY MAP (from the deep investigation — do NOT re-investigate)

The NDA vertical (`ai-advanced-capabilities-nda-r1`) built the execution machinery; it is **disconnected from the analysis lifecycle**. Reuse seams:

### 4a. Open a document in the editable Compose surface (Phase 1 already uses this)
Dispatch on the `workspace` channel:
```
dispatch("workspace", { type:"widget_load", widgetType:"compose",
  widgetData: { compose: { speDriveItemId, speDriveId, sprkDocumentId?, fileName?, activeWorkType? } },
  displayName });
```
- `speDriveItemId` (= `sprk_document.sprk_graphitemid`) is **load-bearing**; `speDriveId` (= `sprk_graphdriveid`) also required or ComposeEditor dies. Both resolved via `$expand=sprk_documentid($select=sprk_filename,sprk_graphitemid,sprk_graphdriveid)`. From the wizard, the **upload result** carries them: `uploadResult.uploadedFiles[0].{id, driveId, name}`.
- `activeWorkType:'agreement-analysis'` scopes the Compose AI toolbar (`getToolsForSurface`). Worktype 100000000 → `'agreement-analysis'` (mapped in `main.tsx`).
- Compose branch: `WorkspacePane.tsx` ~1329-1512; instance-key reuse via `deriveComposeInstanceKey` (`stored:<speDriveItemId>`), so same doc reuses its tab.
- Seed type: `ComposeWidgetSeed` in `.../workspace/composeWidgetData.ts` (fields: speDriveItemId, sprkDocumentId, speDriveId, fileName, activeWorkType, upload?, draft?).

### 4b. RUN the NDA/agreement review (Phase 2)
- **Trigger today:** the "Review an NDA" **chip** (`localActionChips.ts:133` `DOCUMENT_REVIEW_CAPABILITIES = [{ docType:"nda", consumerType:"nda-review", cardLabel:"Review an NDA" }]`), gated on a classified upload. `handleReviewNda` (`ConversationPane.tsx:1134-1150`): `mountFileInCompose(fileId, fileName)` + `chips.dispatchBinding(ndaReviewBindingId, { slots:{ fileIds:[fileId] } })`.
- **Dispatch shape:** `chips.dispatchBinding(bindingId, { slots:{ fileIds } })` → `dispatchConsumer(bindingId, args)` → **`POST {bff}/api/ai/chat/sessions/{sessionId}/dispatch`** (SSE). Runs on the **chat session**. `bindingId` resolved from the **closed capability catalog** by `consumerType:"nda-review"` (`ConversationPane.tsx:381`) — NEVER hardcode (ADR-039).
- **Result → editor (generic, reusable):** terminal `dispatched.result` = `{ overallRisk, flaggedSections[{ sectionRef, quotedText, riskLevel, explanation, standardRef }] }` → `useNdaReviewAdvisoryCommentsBridge.emitFromResult` (detects shape via `isNdaReviewResult`) → dispatches `workspace` `compose_advisory_comments` → `useComposeWorkspaceReceivers.onAdvisoryComments` → `ComposeEditorHandle.placeAdvisoryComments` (anchored TipTap threads via `resolveTargetSpans('strict')`) + `NdaReviewSummaryPanel`. Pure client projection (ADR-040), no 2nd server call.

### 4c. sprk_analysis ↔ session binding (Phase 2/3 durable)
- Server: at session-create, if `HostContext.EntityType == "sprk_analysisoutput"` (const `AnalysisHostContextEntityType`) + `EntityId` is a GUID → repo sets `sprk_aichatsummary.sprk_analysis` FK (`ChatDataverseRepository.cs:69-73`). Also `BindSessionToAnalysisAsync` (`:232-281`).
- Reverse lookup: `GET /api/ai/chat/sessions/by-analysis/{analysisId}` → most-recent session; **404 when none bound** (never mint empty — task 031 rule). **WorkspacePane `existing` effect already calls this + `session_switch` (history restore) when a session exists.**
- **The gap for Phase 2:** the review dispatch needs (a) a **chat session bound to the analysis**, and (b) the uploaded doc referenceable by the dispatch (today `slots.fileIds` = **session-uploaded** file ids; the wizard produces a durable `sprk_document`, not a session file — impedance mismatch to bridge). The wizard currently creates NO session and runs NO review.
- **Phase 3 gap:** on reopen, `session_switch` restores the transcript, but the review's advisory comments must **re-project into Compose** from the ledgered result (not automatic today).
