## 3. 🔵 NEXT STEPS — the tabbed Quick Start feature (DESIGNED, NOT BUILT)

**Owner's goal:** stop showing "create" cards inside the Analysis widget; make analysis creation flow through the shared **Quick Start** modal, now tabbed.

### Locked decisions (owner, 2026-07-29/30)
1. **Analysis widget → a plain dataset-grid widget** "just like Documents/Matters/Projects" — remove the top cards; grid + toolbar only.
2. **Row-click = Option (a): open the OOB `sprk_analysis` form as a modal (Layout 1, 85%×85%)** — same as opening from a record. **DROP the task-031 reopen-session behavior** (no custom `onRecordOpen`; use the DataGrid default). This resolves the old reopen/named-tab question — it's moot now.
3. **`+ New` toolbar → opens the Quick Start modal** (override the DataGrid built-in `create-form`/New command; NOT the OOB create form — replace, not both).
4. **ONE Quick Start modal, extended** (not a copy): Fluent v9 **`Dialog` + `TabList`** (owner approved my finding — there is NO generic modal-shell component; the standardized primitives are `Dialog` + `TabList`, exactly as `PlaybookLibraryShell` composes them). Title in the header bar.
   - **Tab 1 "Create"** = the existing 7 `GetStartedCardsWidget` cards.
   - **Tab 2 "Analysis"** = 3 analysis cards (Agreement Review live; Legal Research + Patent "coming soon"), **identical layout**, expandable later.
   - Opened from the **Assistant menu** → lands on **Create**. Opened from the **Analysis grid `+ New`** → lands on **Analysis**.
5. **Agreement Review card** → **closes Quick Start** + opens the **Create Analysis wizard AS A MODAL** (`CreateRecordWizard embedded={false}` gives its own Fluent Dialog). The wizard does **NOT** open in a tab; on **finish it populates a new tab** (as today) and the Analysis grid tab stays open.
6. **Regarding** pre-set threaded when `+ New` is used inside a record (Matter/Project modal).
7. Fluent v9 `TabList` (subtle/underline "workspace" style).

### Implementation plan (≈8 files, 3 packages) — architecture confirmed
