## Why the numeric parity is real (not just "close enough")

`SprkModal`'s `xl` size (`SprkModal/sizes.ts`, `SIZE_SPEC.xl`) has **no `cap`** (pure `92vw`) and **no `heightMax`** (pure `88vh`) — i.e. for this one size, `uiScale` is provably a no-op (the `heightExpr()`/width-cap branches that apply `uiScale` only fire when `cap`/`heightMax` are defined). `WizardShell`'s `maxWidth="92vw"` + `height="88vh"` therefore produce IDENTICAL computed CSS to what `SprkModal size="xl"` would compute, at any `uiScale`. This is why I did not thread a new `uiScale` prop through either file — omitting it is provably a no-op for `xl` specifically, not an oversight (confirmed by reading `getSurfaceStyle`/`heightExpr` source).
