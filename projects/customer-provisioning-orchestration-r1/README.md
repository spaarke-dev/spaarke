## Problem Statement

Provisioning a new Spaarke customer environment today requires mentally merging three generations of documentation (Gen 1 manual `ENVIRONMENT-DEPLOYMENT-GUIDE.md` with 13 known issues; Gen 2 `Provision-Customer.ps1` + Bicep modules; Gen 3 `sprk_dataverseenvironment` registry). An operator executes five phases by hand with no unified state, nothing records which phase an environment has reached, and per-tenant token metering / silent-failure traps / Model 1 vs Model 2 economics are not addressed. The manual process cannot scale beyond single-digit customer environments per week, cannot support self-service Model 2 admin-consent onboarding, and cannot enforce tenant-isolation invariants structurally.

## Solution Summary

One orchestrated pipeline. L1 = 19 idempotent `IJobHandler` handlers (per ADR-004) implementing every provisioning step. L2 = new .NET 10 App Service control plane with Cosmos DB serverless state, REST + AAD auth, fire-and-forget handler execution via Service Bus, state-reconciler `BackgroundService`, per-customer optimistic-concurrency serialization, crash-recovery, and quarantine semantics. L3 = `/provision-environment` Claude Code operator skill with 15-tool matrix + fallback for MCP disconnects. Ships 8 Dataverse solutions, ~25 Bicep modules, 7 AI Search indexes, 14 canonical KV secrets, 11 new columns on `sprk_dataverseenvironment` registry. Enforces 5 tenant-isolation invariants (I1–I5) via new ArchTests + 6 silent-failure trap post-conditions (T1–T6). Two deployment tiers (Model 2 dedicated / Model 1 shared trial) with per-tenant token metering (D19) enabling fair economics.
