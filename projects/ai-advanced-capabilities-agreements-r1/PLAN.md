## 1. Executive summary

Build the type-agnostic **Agreement Analysis review machine** on the shipped nda-r1 Compose surface and the shipped
hub-r1 platform substrate (spine, fork/promote, wizard, `activeWorkType`, editable-Compose open — all in master).
Six workstreams: **Foundation** (registry mirror + general Action + schema split), **Fidelity** (rename, WS-4
anchoring, DEF-01), **Router** (classifier + orientation + confirmation + explicit path), **Durable-Review**
(FR-16 compose-disposition recall + FR-17 wizard auto-run — the accepted hub Phase-2/3 remainder), **UX-depth**
(batch, bidirectional highlight, confirmations), **Output** (memo + docx/email + Word-comment fidelity).

## 5. Risks

| Risk | Mitigation |
|---|---|
| Mega-file contention (`ComposeEditor`/`ConversationPane`/`ComposeWorkspace` touched by many tasks) | Conservative wave plan — same-file tasks never parallel (TASK-INDEX groups) |
| 128KB ledger cap silently drops big reviews on reopen | Explicit 032 acceptance: chunk/budget or surface — never vanish |
| Promote silent-FK gap (201 without durable bind) | 033 fixes or designs around; acceptance requires `by-analysis` visibility |
| `sprk_analysisoutput` sentinel footgun (EntityId = `sprk_analysis` GUID) | Called out in 033/050 constraints; never query the output table with HostContext.EntityId |
| Hub Q1–Q5 unanswered | Defaults locked (we build picker/param, fix FK, load seeds); 022/033 carry escalation triggers |
| Phase-1 owner UAT may change the wizard-finish seam | 033 checks UAT status first (escalation trigger) |
| Shared-file churn from parallel projects (compose-r5, email-r5, messaging-r3) | `/conflict-check` at task start on hot-path files; rebase early |
| Action rename blast radius (`nda-review` consumerType/bindings) | 002 keeps a deprecation/migration step; escalation if consumers break |
