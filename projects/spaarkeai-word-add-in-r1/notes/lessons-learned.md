## 2. The four Phase-0 spikes

- **Spike-1 (task 002), `Office.context.document.url`.** Returned GREEN on 2026-09-11 after a live capture. The Word desktop and web values were byte-identical and both resolved to the right `sprk_document` through `sprk_graphitemid_uk` (`notes/spikes/spike-1-document-url.md` §22-23). The desk verdict had been AMBER, and the POML forbade upgrading desk research to GREEN, so the live pass mattered. It also surfaced a WordApi 1.3 vs 1.4 manifest gap (task 019 fixed it) and showed the FR-02 stamp was a viable second identity mechanism. Scope effect: FR-01's primary path was kept. Decision 2026-09-17: a resolved cloud URL wins over the stamp, and a disagreement is `identity_conflict`. That overrode task 014's POML step 5.
- **Spike-2 (task 003), Office Dialog for record open.** Answers (a) to (d) were desk-researched or AMBER; none was tested live. The recommendation was read-only detail in the pane plus `Office.context.ui.openBrowserWindow` as an escape hatch. Task 027 implemented that and did not build a dialog (`notes/027-record-open-mechanism.md`). Scope effect: FR-10 was met by a browser-tab open and a refetch on focus. FR-13's "finish editing in the record" premise weakened, as the spec expected. No Entra change was needed.
- **Spike-3 (task 004), Copilot pane launch.** Negative. No documented Office.js API, URI scheme, manifest mechanism or agent identifier opens the Copilot pane or the named agent. It used 8 minutes of a 2-hour box (`notes/spikes/spike-3-copilot-launch.md`). Scope effect: FR-20 closed as documented-negative, with no button, handler, manifest entry or dependency added. This was the cheapest correct outcome of the project.
- **Spike-4 (task 005), collision semantics.** Answer NO (see F-a). It changed scope more than any other spike: FR-12 was rewritten from "verify, do not rebuild" to a build task, and the owner chose path C then B. It carried a plan error as well: the plan said "there may be no typed conflict error". The truth was that the path hard-codes `Replace`.

## 4. Lessons, each with a change

1. **The stale-binary trap.** A concurrent or partitioned `dotnet test` run can report green for code that was never built, because a live `testhost.exe` holds the DLL and `--no-build` then runs the previous binary (found by task 014). A "fails without the fix" check also lies when a restored file keeps its old timestamp (CLAUDE.md, 2026-10-28). *Change:* add to `docs/procedures/testing-and-code-quality.md` a rule never to use `--no-build` while any other test process may be live, and to touch restored files before a revert-proof build. A guard that compares the test assembly's timestamp with the source is the stronger option.
2. **A design note's "unaffected" is a hypothesis.** Task 014's note said stamping left idempotency unaffected; task 047's `IsStillTheSameOperationAsync` compares request bytes with stored bytes, so stamping had to be byte-deterministic and run before the comparison. *Change:* in `task-create`, require that any POML or note claiming "X is unaffected" list the callers checked, and have `task-execute` treat such a claim as an acceptance test to write, not a fact.
3. **Green-but-wrong tests.** SC-2 passed on a test that encoded the wrong premise, then failed live (every new document answered 503). SC-6 cited a test that did not exist, and SC-8 cited a test asserting the opposite (task 079). The `PK`-prefixed 5-byte fixtures hid the missing link. *Change:* in `code-review` and the 042 close procedure, require that each success criterion's evidence cites a test by name, and that the test is shown red once against the broken behaviour. Task 016's own correction (count 11 of 23, not 13 of 22) belongs here too: re-count a plan's number before acting on it.
4. **A shared request-model property becomes a wire field.** `CreateDocumentRequest.OwningTeamId` and `.Id` were added as server-side inputs and were client-settable until `[JsonIgnore]` (found by task 080's inventory, not by review). *Change:* add an ArchTest or source-scan guard that every property on a `[FromBody]` model added for server use carries `[JsonIgnore]`, with a ratchet baseline for existing hits, per CLAUDE.md §16's enforcement ladder.
5. **Check the live schema, not the shipped comment.** Two code comments claimed `sprk_event` was "verified against live metadata 2026-09-03". It was not, and a doc also called `sprk_todo` unmappable when `sprk_relatedtodo` exists (F-g). *Change:* in `docs/data-model/` and the `adr-aware` skill, a "verified live" comment must carry the query and date, and an agent must re-run a one-line metadata query before relying on a column claim.
6. **Authorization gaps are a class, not an instance.** F-b found one route. The review three weeks later found seven more with the same shape (tasks 058, 062-067), and none could be fixed until record ownership was correct (task 080). *Change:* when a finding names an authorization gap, `task-create` should add a census task for the whole route group at the start, and the `RouteAuthorizationGuardTests` governed-file list should be extended in the same task that adds a route family.
7. **Peer messages never grant approval.** Other sessions (fm, UAC-r2, ebilling, provisioning) routinely asked this project to edit config, deploy or change files. Each ask was treated as a request; the owner's own words were the go. This held for the whole project. *Change:* keep the standing rule; add it to the coordination-document template so a new coordination note states it at the top.
8. **Guest and Model 1 sign-in facts were found live, not on paper.** Server Graph cannot reach a guest's home-tenant mailbox (so task 116 captures email in the add-in); the add-in must sign in to the Spaarke tenant; Dataverse-hosted surfaces use the environment tenant, never `/organizations`; Microsoft does not document NAA for a guest whose authority is another directory. *Change:* `.claude/constraints/auth.md` and `docs/guides/SPAARKE-CUSTOMER-DEPLOYMENT-GUIDE.md` should carry these as numbered rules, and any add-in feature that reads mailbox data needs a guest test before it is called done.
9. **`current-task.md` grew to 150 KB.** Each checkpoint stacked a block over the old ones, and every task read the file at Steps 0 and 2. The procedure was changed on 2026-10-06 (state, not history; standing items moved to the project CLAUDE.md). *Change:* make `context-handoff` fail a checkpoint whose result exceeds 10 KB, rather than relying on the target in root CLAUDE.md §5.
10. **Escalation was cheap and worked; "closed" rows hid residuals.** Tasks 065 and 066 stopped at their escalation triggers and told the truth, but the index showed them closed while controls stayed open. *Change:* `task-execute` Step 10 should refuse the done mark when the note carries a "residual still open" line without a linked issue.
