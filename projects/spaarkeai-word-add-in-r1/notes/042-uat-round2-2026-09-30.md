**Why `resolve-identity` → 405 is the strongest single piece of evidence.** Task 042 recorded this exact
route as **401 on 2026-09-17**. A 405 is a *routing* answer: the path now matches a different route that
does not accept POST — which is what happens when our `MapPost` is absent and a `/api/documents/{id}`
route swallows `resolve-identity` as an id. `DocumentUrlIdentityFilter.cs:45` carries a guard against
exactly this collision. **Present on 09-17, gone now** is direct proof of an overwrite, not an inference.

⚠️ **Probe-discipline note.** A first pass probed `resolve-identity` at `/api/office/...` and
`by-message-id` without its path parameter. Both returned 404, and both 404s were **meaningless** —
wrong URLs. Re-deriving every path from source before trusting any 404 is what separated the real
finding from the artifact. Same lesson as 042 §70's earlier "probe artifact".

## 🔴 Systemic findings — this will recur

1. **Last-writer-wins on a shared environment.** Any project deploying its branch to `spaarke-bff-dev`
   silently removes every other project's unmerged routes. Nine overwrites went unnoticed.
2. **The BFF cannot say what it is running.** `/api/office/health` returns a hardcoded
   `"version":"1.0.0"`; `/version`, `/api/version` and `/api/health` are 404. **No commit SHA is exposed
   anywhere**, so "is my code deployed?" is unanswerable without route-probing. That is *why* this went
   unnoticed. Exposing the build SHA would have made it a one-line check.
