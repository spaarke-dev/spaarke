## 2. Item 1 — task-pane width

Office does not let an add-in set the task pane's width: there is no manifest property (XML or unified) and no
Office.js call for it in Word; the user drags the pane edge and Office remembers the width per add-in. Only dialogs
(`displayDialogAsync`) take a size. Task 095 re-confirms this against Microsoft Learn (researcher) and, if a
supported setting exists after all, applies +75 px; otherwise the pane's layout is made to work well at the default
width (which items 2–4 already help).

## 3. The sharing-link defect

`POST /api/documents/{id}/share-link` (`FileAccessEndpoints.cs`, OBO Graph `createLink`) is refused by Graph for files
in SharePoint Embedded containers: *"This sharing scenario is not supported on CSP Container site."* Every Send Email
path that puts a **document sharing link** in the body therefore fails — the Word choice (task 086) and Outlook's
native-compose path both mint one via `shareLinkService.mintDocumentShareLink`. The route's own comment says the
Spaarke email composer uses it too, so the defect is wider than the add-in.
