## The 130e-2 contract (editor)

- **Read:** `GET /api/finance/rulesets/{ruleSetId}` returns `proposals[].firmDescription` (string or null) for each rule's working version.
- **Edit:** `PATCH /api/finance/rulesets/{ruleSetId}/proposals/{policyId}` with body member `firmDescription`:
  - absent or `null` leaves it as it is; `""` or blank clears it; the text is trimmed before it is stored;
  - on a draft working version the draft is edited in place; on a published one the edit creates a new draft that takes the change (a clear included) and the published row keeps its own text (fix round 1 F1: there is no `409` for this any more);
  - a published version's stored text that fails the checks now and that the edit does not touch is left off the new draft (logged with `EBILLING-FIRM-DESCRIPTION-DROPPED`), so it never blocks the edit.
- **Refusals:**
  - `422` `errorCode` `ruleset.invalid` (edit) or `ruleset.publish_invalid` (publish), with `errors[]` entries whose `field` is `"firmDescription"` and whose `reason` is one of `firm_description_too_long`, `firm_description_braces`, `firm_description_markup`, `firm_description_invisible_character`, `firm_description_names_rule`, `firm_description_duplicate`. The text is never echoed. Any other invalid edit stays `400`.
- **Editor rules to mirror client-side** (the server is authoritative): at most 200 characters counted as Unicode scalars; no `{ } < >`; no control, format or separator characters, and no unpaired UTF-16 surrogate (`firm_description_invisible_character`); does not contain the rule set's or the rule's name; not on a Duplicate rule. The Rule Review view (`GET`) and accept now check the rule set's name too (F2d), so a description naming the rule set shows its error before publish.
- **Name check comparison** (fix round 2 F3): both sides are NFKC-normalised and every run of white space is read as one space before a case-insensitive comparison, so a no-break, typographic or ideographic space, a doubled space or fullwidth letters do not get a name past it. A client-side mirror should do the same (JavaScript: `normalize('NFKC')`, then `/\s+/gu` to one space).
- **Editor copy for the name check** (known limit, below): a short rule set or rule name refuses any text that contains it, and a look-alike letter from another script is not caught; the editor explains that the description must not mention the rule set or the rule by name.
- **Server codes that are not editor errors:** writer refusal `firm_reason_invalid` (a direct caller only); log code `EBILLING-FIRM-DESCRIPTION-DROPPED` with reason `firm_description_*`, `firm_description_names_unread` or `firm_description_row_gone` (replay).

## Known limits

- **Deploy order:** the column must exist before the BFF build that carries 130e-1 is deployed (every policy version read selects it). Run the script's `-Apply` (owner's go) and `-Verify` first.
- **No backfill:** existing versions have no description; their Signals carry none (as today).
- **Only billing rule Signals carry a description.** System Signals and other policy domains never set `FirmReason`.
- **C2 (fix round 1):** a published version's row is never updated; a description change on it lands on the new draft the edit creates. (Superseded: "C2 is literal ... 409".)
- **The change-override path (fix round 1):** a base version whose stored text fails the checks (for example set by a form edit) no longer refuses the Procedure change: the text is not copied to the record rule and the drop is logged with the code. (Superseded: "refuses the Procedure change with 422".)
- **Policy-name fallback differs by path (accepted):** the mapper and the replay check the policy's `sprk_name`; the rule set editor and the change-override path check the name they hold for the rule (the policy name, or the base rule's name). When those differ the checks can differ; every path still refuses a text naming the name it holds, and the copy-time checks are the last word.
- **Look-alike evasion (accepted, narrowed in fix round 2):** the name check normalises white space and compatibility forms (F3), but look-alike letters from other scripts (homoglyphs, for example a Cyrillic letter for a Latin one) and words split by punctuation are not caught. 130e-2's editor copy explains the rule.
- **uac-r2 K1: a firm reason already written is never retracted.** `FirmRejectionFindings.ShownFirmReason` (used by `FirmFindingsProjection`) only removes invisible characters and truncates; it does not run `FirmDescriptionRules`. Accepted: `sprk_firmreason` is written only by the writer, on create, after validation (pinned by `FirmReasonWriteSitesGuardTests`). The optional read-side `Validate` was not added: it would change the 130d read-side behaviour its tests pin (a text holding an invisible character is shown stripped today, and a long one is truncated, not refused), so it needs its own decision.
- **uac-r2 K2: the guard's column-set list is hand-maintained.** `PolicyVersionColumnsGuardTests.Selected()` names each `sprk_policyversion` column set; a new set must be added by hand (the class remarks say so). The optional source-scan control (every `"sprk_firmdescription"` literal sits in a known set) was not added.
- **ontology-r1 K2: the writer's own check has no names.** `SignalWriter`'s defence-in-depth check is the content-only `Validate(text)` (no rule set or policy name, no rule type), so a caller that bypassed the mapper would not be held to C4 or the Duplicate rule. The mapper and the replay are the only setters of `FirmReason`, pinned by `FirmReasonWriteSitesGuardTests` Rule 1.
- **ontology-r1 K4: a replay writes the version's CURRENT text.** An edit of the version's description between the evaluation and a later create (re-run, reconcile, a retried after-step) changes what the firm sees on that Signal. This is C1 as designed: the plan never stores the text.
- **`sprk_evidencerefs` trust model (pre-existing, 130d):** the firm findings projection matches the override by the reason codes in the Signal's evidence, which the BFF writes on create; the 130d trust model of that column is unchanged here.
- **A form edit bypasses C2 and the editor checks (O5, accepted):** it can change a published version's text; this affects only Signals created afterwards, and the mapper and the replay re-validate it before it is copied. The projection does NOT re-validate (fix round 2 correction): `ShownFirmReason` only removes invisible characters and truncates (uac-r2 K1, below).
- **Short names may over-refuse:** the C4 check is a case-insensitive containment check, so a very short rule set or policy name refuses any text containing it.
- **Replay read faults:** only a missing row drops the text; any other read fault fails the replay, as every other replay read does.
- **Published predicate:** C2 uses `VersionRow.IsDraft` (the rule set editor's own draft test). DEF-061's `VersionWasPublished` is for Procedure versions, not policy versions.
- **Decided items are not evidence-gated** (Q3, unchanged): they read the Signals the decision resolved.
