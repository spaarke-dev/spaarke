## 2. How it works (code-level flow)

Only the configuration-resolution flows are traced here; token validation, OBO, authorization and client sign-in sequences are other areas (see cross-area pointers).

### 2.1 BFF startup: which identity values are read, from where

1. `AddMicrosoftIdentityWebApi(configuration.GetSection("AzureAd"))` binds the default JwtBearer scheme from `AzureAd:{Instance,TenantId,ClientId,Audience}` [CODE src/server/api/Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:47-49]. The template supplies `Instance=https://login.microsoftonline.com/`, `TenantId=#{TENANT_ID}#`, `ClientId=#{API_APP_ID}#`, `Audience=api://#{API_APP_ID}#` [CONFIG src/server/api/Sprk.Bff.Api/appsettings.template.json:37-42]. A second JwtBearer scheme named `Ciam` is built from `Ciam:Instance` + `Ciam:TenantId` as `{instance}/{tenantId}/v2.0` with `Audience = Ciam:Audience` [CODE AuthorizationModule.cs:59-71]; the dev values are `https://spaarkeextid.ciamlogin.com/` + `7052feba-bfc4-43e0-b09e-65014b429131` and audience = the CIAM BFF app id `4a4d5126-91b0-4865-8e3a-134b7209013e` [CONFIG config/environments.json:60-69]. ### 2.2 Client config resolution (Dataverse-hosted surfaces: PCF, code pages)

1. `resolveRuntimeConfig()` queries Dataverse `environmentvariabledefinitions` + `environmentvariablevalues` for `sprk_BffApiBaseUrl`, `sprk_BffApiAppId`, `sprk_MsalClientId`, `sprk_TenantId` in one batch [CODE src/client/shared/Spaarke.Auth/src/resolveRuntimeConfig.ts:56-61,317-373,454-460]; it fails loudly when the BFF URL or app id is missing, accepts `window.__SPAARKE_MSAL_CLIENT_ID__` as a client-id fallback, and resolves the tenant as env var → Xrm `organizationSettings.tenantId` → anonymous `GET {bff}/api/config/client` [CODE resolveRuntimeConfig.ts:463-520]. The scope is built as `api://{sprk_BffApiAppId}/user_impersonation` [CODE resolveRuntimeConfig.ts:525].
2. The result is cached in memory (5 min) and in `localStorage['__spaarke_rtc__']` (60 min) for full-screen/new-window contexts [CODE resolveRuntimeConfig.ts:67-68,96-137,531-534].
3. `resolveConfig()` builds the MSAL config: clientId from caller → window global → none (throws); tenant from explicit authority → explicit tenantId → `window.__SPAARKE_TENANT_ID__` → persisted runtime config → Xrm; inside a Dataverse host an unresolved tenant **throws** (`tenant_unresolved`), outside it falls back to `https://login.microsoftonline.com/organizations` with an error log [CODE src/client/shared/Spaarke.Auth/src/config.ts:101-162; src/client/shared/Spaarke.Auth/src/tenant.ts:14-25]. Rejected tenant values: `common`, `organizations`, `consumers`, `undefined`, `null`, the MSA tenant GUID, the empty GUID [CODE tenant.ts:39-47].
