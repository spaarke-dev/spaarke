## 2. How it works (code-level flow)

### P1. The `@spaarke/auth` v2 library (used by every PCF, code page and solution that calls the BFF)

**P1-A. Runtime config (`resolveRuntimeConfig`) — pre-auth, session-cookie based**

1. If an in-memory copy is younger than 5 min, return it `[CODE src/client/shared/Spaarke.Auth/src/resolveRuntimeConfig.ts:68,416-420]`.
2. Walk `window` → `window.parent` → `window.top` for `Xrm.Utility.getGlobalContext()` with a `getClientUrl` function `[CODE …/resolveRuntimeConfig.ts:262-293]`. If none: fall back to `localStorage['__spaarke_rtc__']` (60-min TTL, needs `bffBaseUrl`, `bffOAuthScope`, `msalClientId`), else throw `[CODE …:95-128,422-440]`.
3. Capture `Xrm…organizationSettings.tenantId`, validated by `normalizeTenant` `[CODE …:453]`.
4. Query the Dataverse Web API `{clientUrl}/api/data/v9.2/environmentvariabledefinitions?$filter=schemaname eq 'sprk_BffApiBaseUrl' or … 'sprk_BffApiAppId' or … 'sprk_MsalClientId' or … 'sprk_TenantId'` then `environmentvariablevalues`, using `credentials:'include'` (the Dataverse session cookie, **no bearer token**); override value wins over `defaultvalue` `[CODE …:304-386,456-461]`.
5. Throw if `sprk_BffApiBaseUrl` or `sprk_BffApiAppId` is missing; MSAL client id = `sprk_MsalClientId` else `window.__SPAARKE_MSAL_CLIENT_ID__` else throw `[CODE …:464-491]`.
6. Tenant = validated `sprk_TenantId` (env var) → validated Xrm tenant → anonymous `GET {bffBaseUrl}/api/config/client` `.tenantId` (persisted 24 h in `localStorage['__spaarke_bff_tenant__']`, de-duplicated per host, 8 s timeout, 60 s failure backoff) → `''` `[CODE …:493-523,150-244]`.
7. Build `{ bffBaseUrl: normalizeUrl(raw) /* trailing slashes and trailing /api stripped */, bffOAuthScope: 'api://{sprk_BffApiAppId}/user_impersonation', msalClientId, tenantId }`, cache in memory and in `localStorage['__spaarke_rtc__']` `[CODE …:525-543,619-624]`.

**P1-B. Provider selection (`initAuth`)**

1. `initAuth(config)`: if a provider exists and the call would coalesce (no `clientId`, or same `clientId` on a tenant authority) return it without network `[CODE src/client/shared/Spaarke.Auth/src/initAuth.ts:45-78]`.
2. Otherwise serialize through `_selection`; `selectProvider` coalesces same-`clientId` inits, **replaces** a provider stuck on a non-tenant authority once a tenant is discovered (waiting for an in-flight popup via `whenIdle`), and disposes-and-replaces for a different `clientId` `[CODE …/initAuth.ts:88-151]`.
3. `withDiscoveredTenant`: if `resolveTenantSync` finds nothing and a client id is known, call `discoverTenantId(bffBaseUrl)` = cached runtime config → env var `sprk_TenantId` (session-cookie query, needs Xrm or a `*.dynamics.com` origin) → BFF `/api/config/client` `[CODE …/initAuth.ts:158-168]` `[CODE …/resolveRuntimeConfig.ts:559-603]`.
4. `new SpaarkeAuthProvider(config)` → `resolveConfig`: `clientId` = config → `window.__SPAARKE_MSAL_CLIENT_ID__` → **throw**; `bffApiScope` = config → `''` (**no throw**, despite the doc comment); `bffBaseUrl` = config → `window.__SPAARKE_BFF_URL__` → `''`; authority = explicit valid `authority` → `tenantId` → `window.__SPAARKE_TENANT_ID__` → persisted `__spaarke_rtc__` tenant → Xrm frame-walk → if still none: **throw `tenant_unresolved`** when `requireTenantAuthority` (default = `isDataverseHost()`: Xrm reachable in any frame, or hostname matches `dynamics.com|dynamics.cn|microsoftdynamics.us|microsoftdynamics.de|appsplatform.us`), else fall back to `https://login.microsoftonline.com/organizations` with `console.error` `[CODE …/config.ts:101-162,17,36-81]` `[CODE …/tenant.ts:29-60,141-183]`.
5. Rejected tenant values: `common`, `organizations`, `consumers`, `undefined`, `null`, the MSA tenant GUID, the empty GUID, anything that is neither a GUID nor a dotted domain `[CODE …/tenant.ts:39-60]`.
6. A newly created provider eagerly calls `getAccessToken()` to warm the cache `[CODE …/initAuth.ts:57-59]`.

**P1-C. Token acquisition (`SpaarkeAuthProvider` → `InMemoryCache` → `BrowserMsalStrategy`)**

1. `getAccessToken()` → `InMemoryCache.acquire()`: return cached token if JWT `exp` − now ≥ 5 min; share one in-flight acquisition across concurrent callers; a `clearCache` bumps a generation so a late result cannot repopulate `[CODE …/SpaarkeAuthProvider.ts:69-88]` `[CODE …/strategies/InMemoryCache.ts:62-106,148-153]`.
2. `BrowserMsalStrategy` lazily `import('@azure/msal-browser')`, builds `PublicClientApplication({ auth:{clientId, authority, redirectUri}, cache:{ cacheLocation:'localStorage', storeAuthStateInCookie:true }, system.loggerOptions.logLevel:3 })`, `initialize()`, `handleRedirectPromise()` `[CODE …/strategies/BrowserMsalStrategy.ts:137-156,326-347]`.
3. Account selection `_pickAccount`: the account that already produced a token on this page → the only cached account in the authority's tenant (or the only cached account at all) → `null` when ambiguous `[CODE …:278-290]`.
4. Step 1 `acquireTokenSilent({ scopes:[bffApiScope], account })` → step 2 `ssoSilent({ scopes, loginHint })` where `loginHint` = `account.username` (UPN) else `Xrm…userSettings.userPrincipalName` via frame-walk, never the display name → step 3 `acquireTokenPopup` unless `requireSilentOnly`, in which case return `''` `[CODE …:36-69,162-218]`.
5. A result is accepted only if it has an access token whose `exp` (JWT claim preferred, MSAL `expiresOn` fallback) is ≥ 5 min away `[CODE …:306-324]`.
6. `authenticatedFetch(url, init)`: resolve relative URLs through `buildBffApiUrl(bffBaseUrl, url)` (ensures exactly one `/api/` segment); acquire a token per attempt; **throw `AuthError('no_token')` and do not send** if none; set `Authorization: Bearer …`; on 401 `clearCache()` and retry with 500 ms × 2^n backoff up to 3 attempts; then `AuthError('auth_exhausted')`; non-401 errors parsed as RFC 7807 into `ApiError` `[CODE …/authenticatedFetch.ts:7-10,31-99]` `[CODE …/buildBffApiUrl.ts:61-85]`.
7. `useAuth()` returns `{ isAuthenticated, getAccessToken, authenticatedFetch, tenantId (JWT tid of cached token), logout }`, deliberately non-reactive `[CODE …/useAuth.ts:49-58]`.
8. Proactive refresh (`proactiveRefresh:true`): every 4 min, only if a token is cached, invalidate the in-memory entry and re-acquire (refresh-token-backed, silent) `[CODE …/SpaarkeAuthProvider.ts:242-261]` `[CODE …/config.ts:90]`.
9. `logout()`: `BroadcastChannel('spaarke-auth-events')` `{type:'logout'}` to same-origin contexts (each provider cascades `clearAllCaches`), then MSAL `logoutPopup`, falling back to `clearCache` `[CODE …/SpaarkeAuthProvider.ts:52-61,118-122]` `[CODE …/broadcastChannel.ts:19-46]` `[CODE …/strategies/BrowserMsalStrategy.ts:240-258]`. Server-side OBO cache is not invalidated (comment) `[CODE …/SpaarkeAuthProvider.ts:114-116]`.
