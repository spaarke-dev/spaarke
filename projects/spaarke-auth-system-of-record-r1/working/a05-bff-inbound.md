## 2. How it works (code-level flow)

### 2.1 Pipeline order for every request

1. `UseCors()` runs first [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:21]; the default CORS policy is the one built in `CorsModule` [CODE Sprk.Bff.Api/Infrastructure/DI/CorsModule.cs:77-155]. Preflights are answered before authorization runs [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:409] (framework behaviour; asserted by the comment, consistent with the registration order).
2. `SecurityHeadersMiddleware` appends `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-XSS-Protection: 0`, HSTS 1y, `X-Frame-Options: DENY`, CSP `default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` [CODE Sprk.Bff.Api/Api/SecurityHeadersMiddleware.cs:12-24].
3. `UseExceptionHandler` maps `MsalServiceException` → 401 `obo_failed`, `SdapProblemException` → its own status, `AiSpendLimitExceededException` → 429 with `Retry-After`, Graph `ODataError` → its `ResponseStatusCode` (or 500), everything else → 500, as RFC 7807 [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:39-63,80-86] [ADDED by verifier: the 429 and `ODataError` arms were not listed; original cited :30-118]. It re-applies `Access-Control-Allow-Origin: <request Origin>` with `Allow-Credentials: false` if the CORS header is missing on the error response [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:88-94] — note this echoes ANY origin on error responses (see §8).
4. A debug middleware labelled "CopilotAuth" logs, at Warning, for every `/api*` request either "No Authorization header" or the token's `aud`, `iss`, `appid|azp`, `scp` [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:121-158]; the comment says `TODO: Remove before production` [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:122].
5. `UseAuthentication()` then `UseAuthorization()` [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:161-162].
6. `UseAuditEnrichment()` pushes `oid`, `appid`, `obo`, `tenantId`, `correlationId` into the log scope for authenticated requests only, using `CallerIdentity.FromPrincipal` [CODE Sprk.Bff.Api/Infrastructure/Logging/AuditEnrichmentMiddleware.cs:80-116].
7. `UseRateLimiter()` runs last [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:170]; the user partition key is `CallerResolution.ResolveOpaqueCallerKey(user) ?? RemoteIp ?? "unknown"` [CODE Sprk.Bff.Api/Infrastructure/DI/RateLimitingModule.cs:310-323].
8. Endpoint filters (`AddEndpointFilter`) run inside the endpoint, after authorization metadata has been evaluated — this is where all per-resource and principal-resolution filters in §4/§2.6 run [CODE Sprk.Bff.Api/Api/Filters/CallerPrincipalAuthorizationFilter.cs:32-49].

### 2.2 Authentication schemes

**Default scheme — workforce JwtBearer (`"Bearer"`).**
1. `services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)` sets the default scheme [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:47-48].
2. `AddMicrosoftIdentityWebApi(configuration.GetSection("AzureAd"))` registers it [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:49]. The library is Microsoft.Identity.Web 4.14.2 [CONFIG Sprk.Bff.Api/Sprk.Bff.Api.csproj:155] (`Directory.Packages.props` pins 3.8.2 but central management is off [CONFIG Directory.Packages.props:3,22]).
3. The `AzureAd` section carries `Instance=https://login.microsoftonline.com/`, `TenantId=#{TENANT_ID}#`, `ClientId=#{API_APP_ID}#`, `Audience=api://#{API_APP_ID}#` [CONFIG Sprk.Bff.Api/appsettings.template.json:37-42]; in production the three values are Key Vault references `TenantId`, `BFF-API-ClientId`, `BFF-API-Audience` [CONFIG scripts/Configure-ProductionAppSettings.ps1:95-97]; on a customer stamp `AzureAd__TenantId` comes from the intake `tenant_id` and `AzureAd__ClientId` from the H3 per-customer BFF app registration [CONFIG scripts/canonical-secret-catalog/manifest.yaml:574-624].
4. No code sets `ValidIssuers`, `IssuerValidator`, `ValidateIssuer` or `MapInboundClaims` for the default scheme (S2 returned only the `Ciam` block and the `PostConfigure` audience lines) [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:99-167]. Issuer validation is therefore whatever Microsoft.Identity.Web applies for the configured `AzureAd:TenantId` (single-tenant: issuer must match that tenant; `common`/`organizations` would widen it) — library behaviour not present in this repo [LIVE?].
5. `PostConfigure<JwtBearerOptions>(default)` runs once (Interlocked guard) and, when `AgentToken:CopilotAudience` is set, merges `ValidAudience` + any `ValidAudiences` + the Copilot audience into `ValidAudiences` and nulls `ValidAudience` [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:106-126]. Template value: `api://#{COPILOT_SSO_PROVIDER_APP_ID}#/#{API_APP_ID}#` [CONFIG Sprk.Bff.Api/appsettings.template.json:359]. If the final audience list is empty it writes `[CRITICAL]` to stderr [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:134-140].
6. `OnAuthenticationFailed` is chained to log `aud`, `iss`, `appid|azp` and the error for every rejected bearer [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:143-166].
7. Whether the accepted audience set also includes the bare client-id GUID (v2 tokens) depends on Microsoft.Identity.Web's handling of an explicit `AzureAd:Audience` — not provable from repo code [LIVE?].

## 8. Defects, risks and inconsistencies

1. **Medium — debug token logger left in the pipeline.** Every `/api*` request logs at Warning either "No Authorization header" or the token's `aud`/`iss`/`appid`/`scp`; the comment says remove before production [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:121-158]. Noise on every anonymous probe/webhook and a standing cost; no secret is logged.
2. **Medium — exception handler echoes any `Origin`.** On an unhandled exception the handler appends `Access-Control-Allow-Origin: <request Origin>` for any origin when no CORS header is present (credentials `false`) [CODE Sprk.Bff.Api/Infrastructure/DI/MiddlewarePipelineExtensions.cs:88-94]. This bypasses the fail-closed allow-list for error bodies (ProblemDetails incl. `detail`).
3. **Medium — 23 registered `ResourceAccessRequirement` policies with no consumers and a wrong-domain resource extractor.** [CORRECTED by verifier: was "20 registered"] `ExtractResourceId` treats `containerId|driveId|documentId|resourceId|id` interchangeably and the service evaluates them as `sprk_documents({id})` [CODE Sprk.Bff.Api/Infrastructure/Authorization/ResourceAccessHandler.cs:136-157; CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:238-295,297-324]. Any future `RequireAuthorization("canXxx")` inherits a wrong ALLOW/DENY silently; the guard's `PolicyOnlyRoutes` is empty [CODE tests/Spaarke.ArchTests/RouteAuthorizationGuardTests.Ledger.cs:978].
4. **Medium — `TenantRouting` router is inert.** `ITenantEnvironmentRouter` + `TenantEnvironmentRoutingFilter` are registered/defined but no route attaches the filter (S7) [CODE Sprk.Bff.Api/Infrastructure/DI/AuthorizationModule.cs:224-228; CODE Sprk.Bff.Api/Infrastructure/Routing/TenantEnvironmentRoutingFilter.cs:28-41]. Multi-tenant `tid`→environment isolation described by ADR-028 A2/FR-09 does not execute; the de-facto model is one stamp per tenant.
5. **Medium — `AgentAuthorizationFilter` does not pin the agent audience/app.** Any default-scheme user token reaches `/api/agent/*` (then `AiAuthorizationFilter`); the `TODO` admits it [CODE Sprk.Bff.Api/Api/Agent/AgentAuthorizationFilter.cs:80-81].
6. **Medium — ACS Event Grid ingress secret is optional.** The anonymous route's only mandatory controls are the topic allow-list and rate limit; the guard records it as Pending task 161 [CODE Sprk.Bff.Api/Services/Communication/Acs/AcsEventGridIngressService.cs:68; CODE tests/Spaarke.ArchTests/RouteAuthorizationGuardTests.Ledger.cs:1056-1057].
