## 0. Reading rules for the matrix

**Cell format**: `STATUS — client token → inbound check → outbound credential (one line) → pointer`.

**Status vocabulary**
- **WORKS** — the code path is complete end to end for that user type on that surface, and nothing that is specific to the cell is `[LIVE?]`. Every WORKS cell still rests on the global live dependencies G1–G9 below; they are listed once here rather than repeated 200 times.
- **UNTESTED** — a `[LIVE?]` item that is specific to the cell (not merely a G-item) decides the outcome. The deciding item is named.
- **BLOCKED** — the code deterministically denies or fails the operation for that user type (a rights answer of `None`, a 401 at the scheme, an unmapped route, a thrown precondition).
- **NOT SUPPORTED** — no code path exists today, or the shape is out of scope (U5 Model 2 is documented as "what the code would do" per the task).
- **NOT APPLICABLE** — the user type cannot reach the surface by construction (no Dataverse session, wrong IdP, no client identity).

**Global live dependencies (G)** — true for every cell; not repeated per cell. `[LIVE?]` throughout.
- G1 Real token claims (`tid`, `oid`, `acct`, `idp`, `aud` shape, `scp`, `roles`, `idtyp`, claim-type form) — the code reads them; the repo cannot show what Entra issues (a05 §7; x01 #1, #8.1).
