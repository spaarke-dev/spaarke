The role **"Spaarke Ontology Service"** (`b1fb7ee0-bfbe-f111-aaaf-0022482913fc`) holds no privilege on contact at all. Fix: add **AppendTo on contact (Global)** to that role (owner approval; not within the standing approval for Basic User and Core User, and the task forbids role changes, so it was not applied). Evidence: App Insights `spe-insights-dev-67e2xz`, exception `DecisionRecordRefusedException`, 15:13:47Z, 15:16:34Z, repeated on three review ids. No Decision Record was created at any point in the run.
2. **Out-of-band Make Secure leaves the root's Signals and DRs in the business unit team for at least 7 minutes (item 8).** The reconcile ran in `ReportOnly` at 15:42Z. ## 6. #1780 K1: schema before BFF

The 140 schema (the `sprk_regarding*` columns on `sprk_decisionrecord`) must reach an environment **before** any BFF that contains UAC 182's Decision Record lineage row (`SecureChildLineage` row for `sprk_decisionrecord`, line ~100). `SecureChildShareSynchronizer` and `SecureChildReconciliationJob` select those columns without a probe, so a missing column fails the whole secure-child load, not just the Decision Record part. Stated in `docs/guides/SPAARKE-CUSTOMER-DEPLOYMENT-GUIDE.md` section 10.5 ("Ordering: the 140 schema before the BFF"). Spaarkedev1 already had the columns before the BFF with the row was deployed; a missing column was not provoked on dev.
