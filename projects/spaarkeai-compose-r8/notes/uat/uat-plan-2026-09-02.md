## What to test

### A. Save reliability + fidelity (the core of R8)

1. Open a real `.docx` in Compose, edit a paragraph, save. Expect: saves, no spurious warnings.
2. Edit a paragraph **far from** any complex content (image, table, field). Save. Reopen. Expect: **everything else byte-identical** — untouched blocks are cloned, not re-authored.
3. Edit a paragraph that **contains** a footnote ref / content control / text box. Expect: it saves, and you are told by name what was dropped — never silence, never a refusal.
4. **What you should NOT see**: warnings about indentation or paragraph styles. Both were retired this release *with their premises* — they are now carried. If you see either, that is a regression.

### A2. U-0 — the list-toggle guard (new in the 2026-09-02 re-deploy)

Put the caret in a **numbered heading** (e.g. "1.2 Technical Field of the Invention") and open **Paragraph**.

- Expect: **Bullet list and Numbered list are greyed out**, hovering shows *"Headings and numbered clauses
  take their numbering from the document — change it in Word for now."* Blockquote stays enabled.
- Expect in an **ordinary unnumbered paragraph**: both list toggles still work normally.
- **This is the fix, not a new defect.** Clicking that button previously flattened the heading to body text,
  dropped the number, and re-minted the paragraph's identity — which is what you saw in round 1. Editable
  numbering arrives with the Option C project; until then the control refuses rather than destroys.

### B. 🔴 The one decision only you can make — `section-break-flattened`

The residual-loss list ([`COMPOSE-WRITE-RESIDUAL-LOSS.md`](../../../../docs/architecture/COMPOSE-WRITE-RESIDUAL-LOSS.md)) gained a **sixth** §2 row, so the signed set changed and needs your accept/decline.

**To see it**: open a document with an interior section break (a landscape schedule mid-document, or a section with its own header), **edit a paragraph that carries the break**, save.

- **Accept** → the break drops, you are told every time, and the prior version stays in SPE version history.
- **Decline** → carrying an interior `w:sectPr` onto a re-authored block becomes scope. Genuinely harder than the other carries: the renderer detaches and re-attaches the *trailing* section, so an interior one has no carrier.

**This is not a new loss** — editing such a paragraph always dropped it. What was wrong is that the warning fired at *open*, whole-document, and the loss was never listed. It is on the list now.

### C. #858 client cutover — the false-refusal fix

Create a **new** document in Compose (born-in-editor or Browse→upload) and save it.

- Expect: saves normally. The container is now derived server-side.
- The pre-save gate that could say *"your Business Unit has no storage container configured"* is **deleted** — it ran the same derivation client-side over a browser Xrm context and could refuse a save the server would have completed.
- If a container genuinely cannot be derived, you should now get: *"Not saved — this new document couldn't be stored. That usually means your Business Unit has no storage container configured; ask an administrator to set one. Your changes are still here — nothing was lost."*

### D. #699 — advisory comments land on the right clause

Run an AI review that produces findings citing sections ("Section 4.2", "4.2(b)(iii)").

- Expect: each note anchors to the clause it cites.
- A finding whose target text appears **twice** should be reported as ambiguous, not silently placed on the first match.
- A finding produced **live** must never say *"came from an earlier session"* (that is #853, also verified this release).

### E. #573 — Assistant → Compose pre-seed (open item awaiting exactly this deploy)

In chat on a matter with a real document: *"open &lt;doc name&gt; in Compose"*.

- Expect: the Workspace pane opens the Compose tab with the document **loading**, and it survives a refresh.
- This has been open since 2026-07-08 as "not observable in dev"; the issue explicitly asks for post-deploy verification. Either outcome is a result worth recording on the issue.

### F. Apply template

Apply a firm template to a saved document. Expect: template chrome (header/footer/orientation) applied, document body preserved, and **no clobbering** if another tab saved during the merge (#776 — that now refuses rather than silently overwriting).
