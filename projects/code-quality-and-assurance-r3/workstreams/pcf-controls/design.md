## 0. Summary & verdict

The PCF surface is **contract-compliant at the platform boundary but structurally indebted inside it**. The load-bearing contracts hold: every React-consuming control externalizes React 16.14 / Fluent 9.46.2 per ADR-022, every BFF data path routes through `@spaarke/auth` `authenticatedFetch` (no raw fetch/XHR/axios anywhere in source), config resolves from Dataverse environment variables (no live hardcoded secrets), and the retired AssociationResolver is genuinely gone. Security (B+) and correctness discipline (lifecycle cleanup, race guards in the newer hooks, defensive edges) are largely real.

The debt is concentrated in four clusters. (1) **God components at scale**: seven files ≥1,000 LOC totaling ~9,000 LOC — headlined by a single 1,718-LOC React.FC with 86 hook calls — plus a 1,048-LOC control class holding all entity knowledge. (2) **A missing shared PCF-auth seam**: the same `@spaarke/auth` bootstrap glue is copy-pasted across 11 controls (the copy chain is documented verbatim in the file headers), alongside ~530 LOC of verified-dead superseded auth/config code including a rolled-own MSAL class with a hardcoded dev-org redirect URI. (3) **Observability is the weakest dimension (D+)**: raw `console.*` is the only diagnostic mechanism, correlation IDs are never sent, telemetry exists on 2 controls despite plumbed App Insights keys, and user query text / business record names ship in production bundles as unconditional DEBUG logs. (4) **CI has no teeth for this surface**: no workflow compiles or typechecks any of the 19 controls, the only lint runs `continue-on-error` against an all-warn config with a 186-warning baseline, installs bypass lockfile enforcement, and ~22 MB of committed webpack bundles is never verified against source.

**One confirmed live correctness defect** (D2-01, gating): RegardingResolver's write handler drops the resolved `displayName` on its success return, so CREATE-mode staging silently falls back to the picker Primary Name — for `sprk_matter` that is the matter **number**, exactly the failure the v1.4.5 fix was written to prevent. The fix is one line plus a test, and it is the fastest grade-recovery lever: D2 = C+ caps this surface, so tranche A1 lifts the cap.

**51 verified finding IDs** (7 HIGH · 25 MEDIUM · 17 LOW · 2 INFO) → **46 distinct remediation targets** after cross-dimension dedup. ~530 LOC provably dead; ~650 LOC of consolidatable duplication; ~9,000 LOC concentrated in seven 1,000+-LOC files. One first-pass claim (D7-08) was refuted (§3).

## 1. Problem statement

The 19 PCF controls grew control-by-control across many projects with a copy-the-last-control convention (`pcf/CLAUDE.md` literally instructs "adapt the example from SemanticSearchControl") and no CI compilation, lint enforcement, or shared seams for auth bootstrap, logging, or telemetry. The result: platform contracts that humans exercised hard (ADR-022 externalization, `@spaarke/auth` routing) are solid, while everything a CI gate or shared seam would have caught silently accumulated — 11 copies of the same auth glue, seven 1,000+-LOC components, dead superseded MSAL code with a hardcoded dev URL, DEBUG payload logging shipped in production bundles, six manifest namespace schemes, and a module doc whose canonical example would break any control that copied it. One real wrong-data defect (D2-01) also shipped because the seam it crossed (write handler → presave bridge) is untested.

**Evidence base**: 11-dimension parallel read-only fan-out + a Fable adversarial-verification pass over every claim. Verification refuted 1 claim (§3), corrected several line anchors and evidence sub-claims (folded into §2 cells), and strengthened multiple findings (e.g. D5-05's tombstones proved *fully* dead; D10-01's zero-build-step claim reproduced exactly).
