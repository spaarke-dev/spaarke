## 1. Objective

Retarget the Spaarke server backend (`Sprk.Bff.Api` + `Spaarke.Core` + `Spaarke.Dataverse` + `Spaarke.Scheduling` + ~7 test projects) from `net8.0` to `net10.0` with **zero product-behavior change** (one owner-approved carve-out: FR-06 telemetry consolidation), land the required package moves, remediate the 6 concrete hit-sites, and cut over production via a zero-downtime App Service slot swap. The `net462` Dataverse plugin is **out of scope** (sandbox-fixed; never moves). Ships and merges to master FIRST; `code-quality-and-assurance-r3` is re-planned on the net10 baseline afterward (design §11).

## 2. Design principles (design §4 — carried into every task)

1. **Support-lifecycle first, modernization second** — every optional library major-bump is deferred; the retarget stays mechanical and reviewable.
2. **One coherent change, not a drip** — TFM + required package alignment + hit-site fixes + CI/global.json land together on one branch. A half-migrated state (net10 code + 8.0 SDK, or mixed Extensions versions) is its own failure mode. **This is why the plan is a near-serial chain, not a parallel fan-out.**
3. **Runtime and binary never disagree in production** — deploy sequencing (§7) is a first-class deliverable, not an afterthought.
4. **Adversarial verification of "done"** — the behavioral risk areas (H1 workers, H2 DI) are verified by an independent non-author pass (NFR-07), not asserted by the implementer.
5. **The net10 upgrade is a quality forcing-function** — dev-boot DI validation, transitive-CVE auditing, and NU1510 pin-cleanup do quality-gate work for free; lean into it rather than suppressing it.
6. **Defer nothing silently** — every deferred library major is logged with a concrete reason (FR-17 files them as follow-on issues).
