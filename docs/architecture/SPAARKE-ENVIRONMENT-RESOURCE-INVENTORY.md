# Spaarke Environment/Customer Resource Inventory

> **Authored**: 2026-08-31 by `customer-provisioning-orchestration-r1` (owner-mandated inventory ahead of tasks 213.7 / 186)
> **Purpose**: single-page owner-reviewable enumeration of every resource that gets created for a Spaarke customer environment — what it is, what naming pattern, which handler/script creates it, and what lifecycle caveats apply.
> **Authority**: source-cited inline. Where this document disagrees with the cited source, the source wins and this doc is corrected.

---

## How to read this document

Every table row below belongs to **one** of three time-scales — the "Notes" column always states which one:

1. **One-time-per-Spaarke-tier (operator runbook)** — an SPE container-type + its owning app-reg + a shared BFF app-reg are stood up ONCE per tier (Trial 1 / Model 1 / Model 2) via [`SPAARKE-SPE-TOPOLOGY-SETUP-RUNBOOK.md`](../guides/SPAARKE-SPE-TOPOLOGY-SETUP-RUNBOOK.md). All future customers of that tier reuse these. As of 2026-08-30 owner disposition, **zero exist for Trial 1 / Model 1 / Model 2** — only the legacy `Spaarke PAYGO 1` dev container-type + `SDAP-PCF-CLIENT` (`170c98e1…`) owner exist ([topology doc §3](SPAARKE-SPE-CONTAINER-TYPE-TOPOLOGY.md#3-spaarkes-topology)). Task 213 owns the first stand-up.
2. **Per-customer at provisioning time (H0–H14 handlers)** — the L2 control-plane's 19 `IProvisioningHandler` implementations, dispatched by `/provision-environment {customerId}` via `POST /api/runs`.
3. **Once per Spaarke-platform (control-plane one-time bootstrap)** — the L2 control-plane itself (App Service + Cosmos + platform KV + Service Bus queue + EXO sidecar + ACR + fleet UAMI) is stood up ONCE per Spaarke environment (dev / demo / prod) via `platform-controlplane.bicep`. Not per-customer.

**Model 2 clarification (owner, 2026-08-31)**: Model 2 has NO shared-environment concept — **every Model 2 stamp IS a customer** (1 env = 1 tenant = 1 customer). Model 1 has multiple customers in ONE shared env but still ONE shared BFF app-reg per env (topology doc §3A rows 5, 6).

**"Tool / Handler that creates it"** always cites either a specific H0–H14 handler ID, a specific script path, or a specific operator runbook step. Cross-references use the same pointer style as [root `CLAUDE.md` §17](../../CLAUDE.md#17-pointers--where-to-find-everything).
